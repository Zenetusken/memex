# `src/memex/` — Backend conventions

Python 3.12+, pyright `--strict` against `src/memex/`, ruff for lint + format. The full engineering manual is [`docs/GUIDELINES.md`](../../docs/GUIDELINES.md); this is the cheat-sheet.

## Module boundaries

`core/` has no Memex deps — everything else may import from it. Import direction otherwise:

```
agents/ → models/ + observability/ + prompts/ + retrieve/ + index/ + core/
retrieve/ → index/ + models/ + core/
index/ → models/ + vault/ + core/
parse/ → models/ + vault/ + core/ + observability/
enrich/ → models/ + index/ + prompts/ + vault/ + core/
ingest/ → vault/ + core/
mcp/ → agents/ + retrieve/ + vault/ + core/
webui/ → agents/ + vault/ + core/    (+ index/graph_store as a test seam; + index.retitle_document as a write path; + daemon + models.registry for the live mode hot-switch; + models.download for the read-only /resources model-cache status panel; + parse.pdf_render for the source-preview rasteriser; + retrieve.entity_overview for the /entity discovery view)
cli/ → everything
daemon/ → core/                       (vLLM lifecycle is config-driven)
```

A module **may not** import a private symbol (`_foo`) from another module. If something needs to be shared, it gets a public name.

The `agents/ → index/` edge is the lazy-store-open pattern: `agents/answering.py`'s `expand_graph` opens `GraphStore` and `query_tables` opens `TableStore` (Table-RAG Phase 2) inside the node, in a `try/finally` — the agent owns no threaded store handle. Same precedent as `webui/`'s lazy `GraphStore` open. The stores' public surface only (`GraphStore`, `TableStore`, `query_doc_tables`), never private symbols.

The single sanctioned **`agents/ → parse/` edge** is the summarizer's optional GPU handoff: `agents/document_summarizer.py` lazily imports `parse.pipeline.pause_vllm_for_gpu` to free the GPU for the (default-OFF) `models.summarizer` model swap-in (`agents/summarizer_serve.py`). It's a GPU-lifecycle cross-cut, narrow (one function, lazy-imported, dormant unless a summarizer model is configured); `pause_vllm_for_gpu`'s natural home is `core/` (its restart helpers already live in `core/model_serving.py`), and hoisting the whole pause/restart machinery there is the cleaner end-state — deferred only because that path was just hardened (ADR-0015 silent-404) and shouldn't churn for a dormant feature.

**`expand_graph` is DEFAULT-OFF (2026-05-28, `MEMEX_AGENTS__GRAPH_EXPANSION_ENABLED`).** A microscope audit ([[db-audit-2026-05-28]]) proved 1-hop "shares-an-entity" expansion does real work for ZERO answer impact at this corpus scale: an A/B was byte-identical on both cross-doc corpora, and a per-query trace showed the node adds 2-12 neighbour chunks of which the reranker cites exactly 0 — the neighbours are linked by GENERIC entities (`neighbors()` is unranked) and hybrid k=50 already has near-total recall at 47 docs, so there's no missed doc to recover. It's an env opt-in for a large entity-rich vault; the `answer_query` param is ANDed with the setting. The **graph store is kept** for its on-mission consumer: **`GraphStore.related_documents(doc_id)`** — the "explore connections" discovery surface (CLI `memex related`, MCP `related_documents`, webui doc-view "Related documents"). Unlike `neighbors()`, it ranks neighbours by shared-entity SPECIFICITY (Σ IDF over shared entities, excluding entities mentioned by >60% of docs as generic noise) via the pure, unit-tested `_rank_related_documents` — so a doc sharing one rare concept outranks one sharing five generic terms. **The graph-grouping INVERSE — `GraphStore.related_bridges(doc_id)` (2026-05-29, `b48f8b2`, the webui `/graph` "Bridges" view)** — consumes the SAME rows (via a shared `_fetch_shared_entity_rows`) but groups related docs UNDER each shared ENTITY (the bridging concept) instead of under each doc, via the pure, unit-tested `_rank_bridges` → `DocumentBridge{entity, kind, doc_count, strength, docs}`. Bridge `strength = mean(IDF×kind_weight) × ln(1 + doc_count)`: per-edge specificity dominates, fan-out enters LOGARITHMICALLY — a *linear* × fan-out (the first cut) made breadth win and surfaced exactly the generic networking terms (`network`/`IP`/`IPv4`) the view should bury; the log damping promotes specific concepts (`OSI`/`ACL`/`ARP`/`DHCP`). Webui-only discovery (not on `FinalResponse`) ⇒ HARD-gate-neutral; spec `docs/specs/graph-discovery.md`. NB the (opt-in) `expand_graph` still uses the OLD unranked `neighbors()`, not `related_documents`; wiring the specificity ranking into expansion is a documented future hook that only pays off at large-corpus scale (where retrieval misses docs). **The graph's SECOND discovery consumer is entity-centric retrieval (2026-05-28, ADR-0011 build-out, spec `docs/specs/graph-discovery.md`): `GraphStore.entity_profile(name)`** resolves a free-text name (case-insensitive, aggregating across kinds) → its identity (kind(s) + true `doc_count`), the authoritative MENTIONS doc set (capped), and the co-occurring concept neighbourhood via the pure `_rank_co_occurring` (`shared_docs × ln(N/df) × kind_weight`; reuses `_ENTITY_KIND_WEIGHT` + `_RELATED_GENERIC_ENTITY_DF_FRACTION` — the shared specificity filter; the `shared_docs` multiplier is the only new term). The orchestrator **`retrieve/entity.py::entity_overview`** (the `retrieve/ → index/` lazy-store edge, mirrors `related_documents`' callers + ImportError fail-open) composes that with `FTSStore.search_in_docs` (scoped to the mention docs when resolved) / `FTSStore.search` (whole-corpus fallback when unresolved or graph-absent). Surfaces: CLI `memex entity`, MCP `entity_overview`, webui `/entity`. Read-only ⇒ HARD-gate-neutral. **Cypher contract (load-bearing, caught by the opt-in real-ryugraph test):** a `RETURN DISTINCT … ORDER BY <expr>` must `ORDER BY` the PROJECTED ALIAS, not `d.<prop>` — after a `DISTINCT` projection ryugraph drops the original binding from scope. Pinned by `tests/unit/test_entity_profile.py` (pure rank) + `tests/integration/test_entity_overview.py` (orchestrator fakes) + `tests/integration/test_entity_profile.py` (live Cypher, `importorskip`). **`entity_profile` also bridges ACRONYM ↔ EXPANSION (2026-05-28, the resolution deepening):** `DNS` and `Domain Name System` are separate entity_ids, so it computes `EntityProfile.suggestions` (`EntitySuggestion{name,kind,doc_count,relation}`) on BOTH the resolved ("Also see") and unresolved ("Did you mean?") paths — **SUGGEST-only, never an identity merge** (the exact-match `doc_count`/`matched_names`/passages are unchanged; a merge of an ambiguous initialism would assert a false identity). The match is **initialism**, NOT substring CONTAINS (rejected: noisy for popular acronyms, useless for rare): pure `index/initialism.py` (`derive_initialism` = first unicode-alnum char per significant word skipping EN+FR connectors; `looks_like_acronym`; `initialism_matches`). Two directions in `entity_profile`: acronym query → a bounded entity-name scan (only when `looks_like_acronym`); multi-word query → derive its initialism + one exact-name probe. The pure `_gate_suggestions` is conservative: **collision-drop** (≥2 DISTINCT names → ambiguous → no-op, the #256 rule), generic + self exclusion, and a **doc-count floor (`_MIN_SUGGESTION_DOC_COUNT`=2)** that kills cross-domain initialism FALSE-FRIENDS (live: `STP` → the 10-K's 1-doc "Short-term portion"). **The residual `STP` gap is NER, not resolution** — the graph has no `STP`/`Spanning Tree Protocol` entity to bridge to (enrich stored `spanning`), so `STP` stays the honest FTS fallback with 0 suggestions; the root-cause fix — better entity extraction upstream — SHIPPED 2026-05-29 as the OTTER NER swap (ADR-0012, [[bert-ner-enrich-scope-2026-05-28]]; see the enrich-backend rule under Type discipline). Pinned by `tests/unit/test_initialism.py` + the bridge cases in `test_entity_profile.py` / `test_entity_overview.py`. **The co-occurring NOISE filter (2026-05-28, `AgentsSettings` → `_cooccurring_min_shared_docs`, FAIL-OPENS to the default outside bootstrap):** `cooccurring_min_shared_docs` (default 2; `_rank_co_occurring` only) is a neighbourhood floor that drops single-doc co-mentions (~69% of the real noise — ports/sizes at `shared_docs=1`). It's corpus-AGNOSTIC + structural (zero per-corpus tuning) → it scales to any vault. **The curated by-NAME `entity_stopwords` list was REMOVED 2026-05-29** (with `_normalize_stopwords` + the `stopwords` param on both rankers + the `NoDecode` import): a hand-curated per-corpus name list — one user's `CR350` course code — doesn't generalise to a local-first app run on arbitrary corpora, and the [[bert-ner-enrich-scope-2026-05-28]] OTTER NER backend (now the live enrich entity extractor) types entities cleanly UPSTREAM, so it no longer earned its keep. Don't reintroduce a curated name list; fix entity noise at the extractor. Pinned by the floor cases in `test_entity_profile.py` (unit + real-graph) + `test_related_documents.py`.

The single deliberate exception is `webui/app.py` re-exporting `GraphStore` from `memex.index.graph_store` at module top — `tests/integration/test_webui.py` monkeypatches `memex.webui.app.GraphStore.open`, which only works if `GraphStore` lives at the module level. The route handler runs the open lazily and falls back gracefully when ryugraph isn't installed.

## Type discipline

- **`src/memex` is pyright `--strict` clean (0 errors, 0 warnings).** Keep it that way — `uv run pyright` is a gate.
- **Untyped third-party libs get local stubs, not silence.** Libraries that ship no usable types (langgraph, lancedb, pypdfium2, pyseccomp, …) have minimal `.pyi` stubs under `stubs/` (wired via `stubPath`), covering only the surface Memex uses — see `stubs/README.md`. For libs that ship a partial `py.typed` (torch, transformers, openai, typer), don't shadow them with a competing stub; fix at the call site with precise annotations / `cast()` / a single typed wrapper (e.g. `registry._from_pretrained`, `registry._bf16`). `# type: ignore[rule]` is a last resort and always carries a trailing `# reason`. A dynamic `pydantic.create_model(...)` should pass `__base__=TheStaticModel` so pyright keeps the field types.
- **No untyped `Any`.** If you need it, add a one-line comment explaining why.
- **Pydantic models cross module boundaries.** Dicts and tuples are module-internal only. Shared types live in `core/types.py`.
- **Node returns use `TypedDict`.** See `agents/answering.py:AnswerStateUpdate` — `total=False` catches state-key typos at type-check time.
- **`complete_structured` is generic over schema.** `tuple[T, int]` where `T = TypeVar("T", bound=BaseModel)`. Don't break that.
- **Bound LLM-emit `str` fields with `max_length=N`.** xgrammar enforces the bound at the JSON-schema grammar level, so the model cannot emit a runaway string that would trip `max_tokens` mid-emission and crash JSON validation. Established by the v6 fix to `SufficiencyAssessment.reason` (was unbounded → 2000-char ramble on counterfactual queries → eval crash) and extended to `DraftAnswer.summary`, `CitedClaim.claim`, `ExtractedEntity.name`, `ExtractedEntity.span_text` (`VerificationResult.ungrounded_reasons` was in this set but is **no longer model-emitted** — see the CAVEAT below). Also cap `list[T]` LLM-emit fields with `max_length=N` (e.g., `DraftAnswer.claims` at 8; `EntityList.entities` + `CitationList.citations` at 24). When adding a new structured-output schema, audit every `str` and `list[...]` field for an explicit bound. **The entity/citation list bounds (2026-05-24) are load-bearing**: an *unbounded* `EntityList.entities` made the enrich step fail ~56 chunks on the 10-K's dense financial tables — the model emitted a runaway entity list that ran past `max_tokens` and truncated the JSON ("Model output did not match the requested schema"), dropping the whole chunk. Bounding the list (xgrammar enforces maxItems) + raising the enrich per-call `max_tokens` to `_ENRICH_MAX_TOKENS=3072` took it 56→4. NB this was the *real* fix; the chunker `MAX_CHUNK_MULTIPLIER` cap (word-budget) is a no-op on word-light/char-heavy tables. **CAVEAT — string `max_length` is NOT reliably enforced at DECODE (2026-06-06):** the guided-decode backend enforces JSON STRUCTURE + integer-list `maxItems`, but a model can still ramble a FREE-TEXT string past `max_tokens` and truncate the JSON REGARDLESS of `max_length` (a 1-claim `/ask` verify whose `ungrounded_reasons` ran 1218+ chars crashed the slide-decks `memex eval` → `EOF while parsing` → `ModelCallError`; in production this propagated out of `/ask` as a 500). So for ramble-prone free-text fields, `max_length` is only POST-HOC pydantic validation, not a decode-time guarantee. **Fix (the verifier): the guided-decode schema is now the reason-less `agents/answering.py::VerifyIndices`** (grounded/ungrounded index lists ONLY; the `/ask` verify node AND `agents/grounding.py::bounded_verification`/`ground_claims` share it) — the free-text reasons field is OFF the decode path; per-claim reasons are CODE-GENERATED by the deterministic backstops (numeric/name-only/missing) on the in-code `VerificationResult` (which keeps the field). The `verify_grounding/v2` prompt is UNCHANGED (it still asks for reasons; the grammar simply doesn't emit them — the grounded/ungrounded indices are emitted first and unchanged, so `eval-summary` stays byte-stable). **Defense-in-depth:** the `/ask` verify node now FAIL-CLOSES on any `ModelCallError` (→ all-ungrounded → `route_after_verify` → refuse, never a 500/crash, mirroring `ground_claims`), and `eval/runner.py::run_eval` isolates a per-query error into a DISTINCT bucket (`EvalReport.error_count`, excluded from refusal_cf/refused — an errored counterfactual must never false-pass as a correct refusal). Validated: slide-decks `memex eval` now COMPLETES (error 0); cr350-multidoc/annual-report `refusal_cf=1.0` ×2 with byte-stable answer counts; eval-summary 6/6 / 0-leak. Pinned by `test_schema_bounds.py::test_verify_guided_schema_excludes_free_text_reasons`, `test_answering_with_fakes.py::test_verify_fails_closed_on_model_error`, `test_eval_runner_resilience.py`.
- **Chart-OCR output is LLM-readable markdown, not raw LaTeX.** Nemotron-Parse-v1.2 (the default chart-OCR backend) emits `\begin{tabular}{cc} **On Time 22** & **Late 8**\\ \end{tabular}` which the assess/answer LLMs cannot parse as structured data. The v7 fix (`chart_ocr_backend._normalize_latex_tabulars` + `_split_label_number_cells`) post-processes Nemotron output into markdown tables (multi-row) or key:value bullets (single-row chart summaries where each cell matches `<label> <number>`). When extending the chart-OCR backend with new models, keep emission in LLM-native markdown — pipe-tables, bullet lists, prose sentences. Raw LaTeX in chart-extracted blocks is a regression.
- **The canonical `.md` is CONTENT-ONLY; `[chart-extracted]` blocks live in a manifest SIDECAR and are RE-ATTACHED at index time** (audit-10 #362, 2026-06-02). The vault `.md` keeps a clean `<!-- image -->` placeholder where each chart was — the chart-OCR output is persisted on `ParseStage.chart_extractions: list[ChartExtraction{placeholder_index, markdown}]` (`core/manifest.py`) and re-inserted by `core/text.reattach_chart_extractions(body, blocks)` in `index/pipeline.py::index_document` BEFORE `linearize_gfm_tables`, reproducing the historical stitched body BYTE-FOR-BYTE. This is the `[table-rows]` pattern, sidecar-backed (chart-OCR output is NON-re-derivable from the `.md`, unlike a GFM table). **Load-bearing: `reattach_chart_extractions` MUST stay byte-identical to the old `_stitch_chart_extractions`** (same framing `\n\n[chart-extracted]\n{md}\n[/chart-extracted]`, same last-to-first splice) — chunk_ids are content-addressed, so a divergence churns every chunk_id + drifts eval anchors. Pinned by the golden byte-equality oracle `test_pipeline_chart_ocr.py::test_golden_byte_equality_*` (which keeps the retained-but-unused `_stitch_chart_extractions` as the reference) + the build/reattach/manifest-roundtrip tests. `IMAGE_PLACEHOLDER_RE` has ONE home in `core/text.py` (shared by `build_chart_extractions` in parse + the re-attach in index). BACK-COMPAT: `reattach(body, [])` is identity, so a legacy/un-migrated `.md` that still carries inline blocks indexes exactly as today. The webui raw-doc-view now shows the clean `.md` (no inline chart blocks) — the desired source-of-truth view; the chunks the LLM sees are unchanged. Migration of the 6 affected docs (2026-06-02): re-parse OR a GPU-free direct-split (extract on-disk blocks → clean `.md` + sidecar), validated by 627/627 chunk_id byte-stability + a live chart `/ask` (NVLink C2C 900 GB/s answered). **Enrich parity (#394, FIXED 2026-06-02):** `enrich/pipeline.py` now applies the SAME body transform before `chunk_document` — `reattach_chart_extractions` then `linearize_gfm_tables`, read from the parse manifest sidecar, mirroring `index_document` — so enrich and index chunk identical bytes and a chart-bearing chunk's MENTIONS attested `chunk_id` resolves in FTS (exact-passage discovery, not the name-search fallback). Only the chunking copy is transformed: `doc.body` stays CLEAN for the wikilink + course-ref writes; `reattach(body, [])` is identity for the non-chart docs. The 6 chart docs were re-enriched. The summarizer is unaffected (it reads already-indexed chunks via FTS, never re-chunks).
- **Chart-extracted blocks are visible to assess/answer/verify** (P3.3 v7, 2026-05-23). Earlier defenses (v3/v5/v6) stripped `[chart-extracted]...[/chart-extracted]` blocks from the chunks before rendering the assess/answer/verify prompts because raw LaTeX (~500+ chars per block) ate the `truncate(1200)/truncate(1800)` budget. With v7's compact markdown emission (~50-150 chars per block), strips are no longer needed and would actively block chart-content answering. Do not re-introduce strips in `agents/answering.py:assess`, `answer`, or `verify` — chart blocks should flow through to the LLM. The FTS-side strip in `index/fts_store.py` (P3.3 v3 defense) is retained: BM25 keyword search on chart-block content adds noise without helping retrieval recall. The blocks reach the chunks via the index-time re-attach above (the `.md` is clean).
- **Chunker treats `# H1` lines INSIDE `[chart-extracted]` blocks as inert** (P3.3 v7 chunker fix, 2026-05-23). Nemotron-Parse emits H1 prefixes for chart-figure-section labels (e.g. `# Minimal lead-time`, `# Inter-operability`) which look like document headings to a naive regex. `core/text.py::chart_extracted_spans` + `is_inside_any_span` are the helpers; `index/chunker.py::_split_into_sections` and `_heading_path_at` filter heading matches inside those spans. The fix recovered slide-decks Q31 ("4 design principles") + Q18 ("NVLink C2C 900 GB/s" via chunker reflow) + annual-report Q03 ("Data Center revenue $193.737B"). When extending chart-OCR or the chunker, preserve this contract — pinned by `tests/unit/test_chunker_chart_aware.py::test_h1_inside_chart_block_does_not_split_section`.
- **The verify node filters phantom claim-indices** (P3.3 v7 verify-fix, 2026-05-23). The verifier LLM can emit indices > n-1 when distracted by chunk content not in the draft (xgrammar `max_length=n` bounds list length but not index values). `agents/answering.py:verify` filters to `[0, n-1]` and conservatively treats indices missing from BOTH `grounded` and `ungrounded` as ungrounded. Pinned by `tests/integration/test_answering_with_fakes.py::test_verify_filters_phantom_indices` + `test_verify_missing_index_treated_as_ungrounded`.
- **The verify node has a deterministic NUMERIC-GROUNDING BACKSTOP** (2026-05-31, `agents/answering.py::verify`). The single greedy `verify_grounding/v2` LLM call rubber-stamps a COMPUTED AGGREGATE — a summed/totalled table value the doc never states — as grounded via its "literal reading of a table row / structural adjacency is sufficient" rule (the live 10-K fabrication `$159,748,343` = a sum of exec-comp PSU cells, asserted for an absent "director stock options"; the earlier recorded `$16,042M` vs cell `16384`). A **4th deterministic demotion filter** (after the phantom/missing/contested filters, before `VerificationResult` is built — same shape, preserving the parallel-array invariant) demotes a still-grounded claim to ungrounded when ALL of: (1) `_chunk_has_markdown_table(chunk)` — the cited chunk carries a GFM `|---|` separator OR the `[table-rows]` marker (the cross-cell-aggregate SITE; **prose-cited rounded headlines like "$216 billion" are exempt** — table-presence narrowing), (2) `_claim_scoped_figures(claim)` is non-empty — the claim asserts a LARGE figure (`|coerce_number|` ≥ `_NUMERIC_BACKSTOP_MIN_MAGNITUDE`=1e4; years/small-counts/`x`-or-%-values are out of scope), and (3) `_figure_supported_by_chunk` is False for EVERY scoped figure — none equals a cited-chunk number under the Table-RAG tolerance `max(1, 1e-6|b|)`, allowing ONLY a thousands/millions/billions **denomination shift** (a power of 1000, `_NUMERIC_DENOMINATION_FACTORS`) so "$22.5 billion" grounds in a "22,500" $-millions cell but a x10 mis-scale or a digit-substring spanning two cells is rejected. Two load-bearing exemptions: the synthetic Table-RAG `#sql0001` chunk is SKIPPED (its aggregate is already recompute-gated upstream AND `_build_synthetic_chunk`'s `%g` framing renders a ≥1e6 value unreadable to `coerce_number`, so a verbatim re-check would wrongly drop it); and the gate demotes only when EVERY scoped figure is unsupported, so a claim stating a rounded headline AND an exact figure (gte-05 "~800M … 788M") is kept on the verbatim 788M. **Demotion-only ⇒ HARD-gate-safe by construction**: a zero-grounded result routes to `refuse` via the existing `route_after_verify`; a partial draft just drops the aggregate (the partial-grounded path). Reuses `table_sql.coerce_number` (NEVER a second number parser). Kill-switch `AgentsSettings.numeric_grounding_backstop_enabled` (default True, fail-open) → `AnswerState.numeric_grounding_backstop`. **The prompt-floor alternative was BUILT then REVERTED** — tightening `verify_grounding/v2` + `answer/v3` to forbid cross-cell aggregation over-suppressed legitimate SUPERLATIVE reads (ar-15 "lowest total compensation $321,309", a verbatim min cell, refused via the verifier) and added blast radius on every answer for redundant benefit; the deterministic backstop is the sole load-bearing fix. **LESSONS:** (1) a single greedy LLM verify call CANNOT reliably reject a computed aggregate (it "sees" the component cells and judges the sum "supported") — a fabricated NUMBER needs a deterministic verbatim-presence check, the free-text analogue of the Table-RAG row-verbatim boundary; (2) the live fabrication is borderline/non-deterministic (~1-in-10 mint under greedy AWQ) — the backstop is the deterministic GUARANTEE for the minting runs, validated by a real-chunk probe (demotes the fabrication on 8/8 live comp-table chunks) + the integration test, not by waiting for a live mint. Pinned by `tests/unit/test_numeric_grounding.py` (the pure matchers + the x10/boundary-span adversarial probes) + `test_answering_with_fakes.py::test_numeric_backstop_*` (demote / keep-verbatim / millions-denomination / sql-exempt / prose-exempt / rounded-plus-exact / kill-switch / end-to-end-refuse).
- **The verify node has a deterministic NAME-ONLY GROUNDING BACKSTOP** (2026-06-03, `agents/answering.py::verify`, the sibling of the numeric backstop above). The same single greedy `verify_grounding/v2` LLM call rubber-stamps a BEHAVIORAL claim cited to a chunk that merely NAMES the entity — its "literal reading / structural adjacency is sufficient" rule (written for Table-RAG literal reads) grounds "RBAC assigns permissions based on a user's job function" against a bare slide that just LISTS `Role-Based Access Control (RBAC)`. It's **a property of the shared gate** (the same leniency surfaced on the present-as-answer bridge, fixed there presentation-only by the name-only guard; audit-11), now closed on the `/ask` HARD-gate path. A **5th deterministic demotion filter** (after the phantom/missing/contested/numeric filters, before `VerificationResult` is built — same parallel-array invariant) demotes a still-grounded claim to ungrounded when BOTH: (1) `core/text.is_name_only_chunk(chunk.text)` — the cited chunk is a bare list/heading (≥2 short non-heading lines, no ≥8-word line, **no markdown table / `[table-rows]` / `[chart-extracted]` block** → Table-RAG and the numeric backstop are NEVER touched, byte-disjoint by construction); reads the **full `chunk.text`**, not the truncated prompt render (as the numeric backstop does), and (2) `core/text.claim_asserts_behavior(claim.claim)` — the claim carries a **behavioral/property/comparative predicate** from a curated **bilingual (EN+FR)** marker set (`assigns`/`assigne`, `evaluates`/`évalue`, `based on`/`basé sur`, `superior`/`supérieur`, `faster`/`than`, …) AND does NOT match a pure membership/existence pattern (`is one of`/`est un de`, `includes`/`fait partie`, `such as`, an enumeration — checked FIRST). It keys on the **PREDICATE CLASS, not lexical chunk-overlap** → cross-language robust (the name-list chunk is French, the claim often English). **FAIL-OPEN is the load-bearing safety property:** a membership/value/UNKNOWN predicate → KEEP (no demotion), so the worst case of a marker-set coverage gap is a behavioral-name-list claim SLIPPING THROUGH (the status-quo over-grounding) — never a NEW over-refusal. Combined with **demotion-only ⇒ HARD-gate-safe by construction** (a zero-grounded result routes to `refuse` via `route_after_verify`; a partial just drops the bad claim), this can NEVER manufacture a refusal a prompt change couldn't bound. - **The aggregate gate's safety is an INDEPENDENT Python row-selection oracle — NEVER let SQLite own the WHERE** (2026-05-31, `agents/table_sql.py`, adversarially audited). `_recompute_aggregate` re-selects the contributing rows in PURE PYTHON via `_parse_where_predicate` and re-derives the scalar over the original cell text, so the agreement check `sqlite_value == python_value` compares TWO INDEPENDENT row selections. **A "decompose-and-verify via the SQL stack" redesign (run the LLM's aggregate for the scalar, then `SELECT * FROM t WHERE W` to materialize the rows, recompute over THOSE) is UNSAFE and was rejected — do not reintroduce it.** Because the `__num` companion is built by the SAME `coerce_number` the recompute uses, `S = SUM(__num over W)` and the re-sum over the SELECT*'s rows are ALGEBRAICALLY EQUAL for every W (the check degenerates to "SQLite agrees with SQLite") — empirically confirmed to SHIP `WHERE rowid <= 2` / `WHERE v > (SELECT AVG(v))` / `WHERE v % 20 = 0` partial-sums framed as the total, and `random()` non-reproducible scalars. The recall wins come from WIDENING the independent oracle, not from the SQL-stack rearchitecture. **The oracle (`_parse_where_predicate`) covers `col <op> value`, `col [NOT] IN (...)`, `BETWEEN`, `IS [NOT] NULL`, `LIKE`, and a single level of `AND`/`OR`** — each independently evaluated, so any parse divergence from sqlite just makes the sums DISAGREE → REFUSE (a widening bug can only false-refuse, never ship a wrong subset). Dangerous WHEREs (`rowid`/`random`/`glob`/sub-`SELECT`) are explicitly rejected (`_DANGEROUS_WHERE_RE`) + don't match any safe atom. **Three companion safety guards, each adversary-pinned in `test_table_sql.py`:** (A1) `SUM/AVG/MIN/MAX` must target the `<col>__num` companion — a raw-text-column aggregate is a coercion-misread surface (sqlite's lenient prefix-coercion `'350000.75 deferred'`→350000.75 vs `coerce_number`→350000 within the ±1 floor); (A2) a superlative `ORDER BY` must target `__num` so sqlite sorts NUMERICALLY (a text ORDER BY sorts lexically `'9'>'10'` and the ±1 extremum tolerance framed the WRONG row as "highest"); (coercion-soundness) refuse an aggregate/superlative whose contributing cell coerces but is NOT `core/text.is_canonical_number_cell` — the shared-`coerce_number` blind spot (malformed `1,2,3`→123, mixed-separator European). **`_load_tables` builds the text columns `COLLATE NOCASE`** so sqlite `=`/`IN`/`LIKE` align with the case-insensitive recompute → the dominant value-linking false-refuse (`'us'` vs stored `'US'`) ships the correct value instead of refusing. **Known residual (documented, not closed):** locale (`'1.000'` European decimal-vs-thousands) + unit (`'5m'` metres-vs-million) coercion ambiguity needs context the system lacks and does not occur in the US-format corpora. Module-local subclasses are fine as long as they inherit from `MemexError` — current ones: `CircuitBreakerOpen` (core/breakers.py); `ModelNotConfigured` (models/registry.py); `VLMUnavailable`, `PDFRenderError` (parse/vlm_backend.py); `ChartOCRUnavailable`, `PDFFigureRenderError` (parse/chart_ocr_backend.py); `DoclingUnavailable`, `DoclingTimeout`, `DoclingCrashed`, `SandboxLoadFailed` (parse/docling_backend.py); `PyMuPDFUnavailable`, `PyMuPDFTimeout`, `PyMuPDFCrashed` (parse/pymupdf_backend.py); `DaemonAlreadyRunning`, `DaemonStartTimeout` (daemon/supervisor.py).
- Every raise carries a `context: dict` with the values a user needs to act on the error.
- Recoverable errors set `recoverable=True` so the pipeline knows to resume on retry.
- **Narrow `except` clauses.** Never `except BaseException` (would swallow `CancelledError`, `KeyboardInterrupt`, `SystemExit`); never `except Exception` unless you re-raise the cancellation cases above explicitly. When wrapping a third-party SDK exception, check the module via `type(e).__module__.startswith(...)` rather than catching the broad base class.

## Async / sync

- **Async**: filesystem I/O, model calls, database operations, HTTP, MCP transport.
- **Sync**: token parsing, formatting, chunker, pure transformations.
- CPU-heavy sync work called from async code goes through `asyncio.to_thread` (`models/registry.py` does this for sentence-transformers `encode`; `index/fts_store.py` for sync SQLite).
- **Per-resource locking** is `asyncio.Lock` for stores serving async callers (`index/fts_store.py::FTSStore._lock` gates multi-statement writes; `vault/store.py::_DOC_LOCKS` gates per-doc write paths) and `threading.Lock` for state that crosses both sync and async callers (`agents/answering.py::_COMPILED_GRAPH_LOCK` gates the lazy graph compile). Don't mix the two — pick by who the callers are. The `models/registry.py::_locks` per-model dict + the breaker's lock are the canonical patterns to copy.

## Logging

structlog. Bind once per run scope at the entry point (`bind_run_context(correlation_id, ...)`), bind node/function scope locally (`log = logger.bind(node="rerank")`), emit `log.info("event", k=v)`. **Never** `extra={...}` (lost), **never** f-strings in event names (kills aggregation in Langfuse).

- **Fakes accept forward-compatible kwargs.** When you write a stand-in for `complete_structured` (or any other function with optional kwargs), terminate the signature with `**_kw: object` so adding a new kwarg upstream doesn't silently break the test. Same for `docling_convert` and other monkeypatch targets — the kwarg-signature bug from 2026-05-20 was the canonical example.
- **Patch via `monkeypatch.setattr`**, never direct module-attribute mutation. The latter leaks into subsequent tests in the same session.

## When adding a new module

1. Check the architectural blueprint — module signatures are already designed in `docs/IMPLEMENTATION-PLAN.md` §1.
2. Update `src/memex/<module>/__init__.py` to re-export the public surface.
3. Add an integration test under `tests/integration/`. Fake every external (`monkeypatch.setattr`).
4. Wire to the CLI under `cli/commands.py` if user-facing.
5. Update `docs/ROADMAP.md` if the module ships a phase deliverable.
