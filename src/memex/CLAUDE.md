# `src/memex/` — Backend conventions

Python 3.12+, pyright `--strict` against `src/memex/`, ruff for lint + format. The full engineering manual is [`docs/GUIDELINES.md`](../../docs/GUIDELINES.md); this is the cheat-sheet.

## Module boundaries

`core/` has no Memex deps — everything else may import from it. Import direction otherwise:

```
agents/ → models/ + observability/ + prompts/ + retrieve/ + index/ + core/
retrieve/ → index/ + models/ + core/
index/ → models/ + vault/ + core/
parse/ → models/ + vault/ + core/ + observability/
enrich/ → models/ + index/ + prompts/ + vault/ + core/
ingest/ → vault/ + core/
mcp/ → agents/ + retrieve/ + vault/ + core/
webui/ → agents/ + vault/ + core/    (+ index/graph_store as a test seam; + index.retitle_document as a write path)
cli/ → everything
daemon/ → core/                       (vLLM lifecycle is config-driven)
```

A module **may not** import a private symbol (`_foo`) from another module. If something needs to be shared, it gets a public name.

The `agents/ → index/` edge is the lazy-store-open pattern: `agents/answering.py`'s `expand_graph` opens `GraphStore` and `query_tables` opens `TableStore` (Table-RAG Phase 2) inside the node, in a `try/finally` — the agent owns no threaded store handle. Same precedent as `webui/`'s lazy `GraphStore` open. The stores' public surface only (`GraphStore`, `TableStore`, `query_doc_tables`), never private symbols.

The single deliberate exception is `webui/app.py` re-exporting `GraphStore` from `memex.index.graph_store` at module top — `tests/integration/test_webui.py` monkeypatches `memex.webui.app.GraphStore.open`, which only works if `GraphStore` lives at the module level. The route handler runs the open lazily and falls back gracefully when ryugraph isn't installed.

## Type discipline

- **`src/memex` is pyright `--strict` clean (0 errors, 0 warnings).** Keep it that way — `uv run pyright` is a gate.
- **Untyped third-party libs get local stubs, not silence.** Libraries that ship no usable types (langgraph, lancedb, pypdfium2, pyseccomp, …) have minimal `.pyi` stubs under `stubs/` (wired via `stubPath`), covering only the surface Memex uses — see `stubs/README.md`. For libs that ship a partial `py.typed` (torch, transformers, openai, typer), don't shadow them with a competing stub; fix at the call site with precise annotations / `cast()` / a single typed wrapper (e.g. `registry._from_pretrained`, `registry._bf16`). `# type: ignore[rule]` is a last resort and always carries a trailing `# reason`. A dynamic `pydantic.create_model(...)` should pass `__base__=TheStaticModel` so pyright keeps the field types.
- **No untyped `Any`.** If you need it, add a one-line comment explaining why.
- **Pydantic models cross module boundaries.** Dicts and tuples are module-internal only. Shared types live in `core/types.py`.
- **Node returns use `TypedDict`.** See `agents/answering.py:AnswerStateUpdate` — `total=False` catches state-key typos at type-check time.
- **`complete_structured` is generic over schema.** `tuple[T, int]` where `T = TypeVar("T", bound=BaseModel)`. Don't break that.
- **Bound LLM-emit `str` fields with `max_length=N`.** xgrammar enforces the bound at the JSON-schema grammar level, so the model cannot emit a runaway string that would trip `max_tokens` mid-emission and crash JSON validation. Established by the v6 fix to `SufficiencyAssessment.reason` (was unbounded → 2000-char ramble on counterfactual queries → eval crash) and extended to `DraftAnswer.summary`, `CitedClaim.claim`, `VerificationResult.ungrounded_reasons` items, `ExtractedEntity.name`, `ExtractedEntity.span_text`. Also cap `list[T]` LLM-emit fields with `max_length=N` (e.g., `DraftAnswer.claims` at 20; `EntityList.entities` + `CitationList.citations` at 24). When adding a new structured-output schema, audit every `str` and `list[...]` field for an explicit bound. **The entity/citation list bounds (2026-05-24) are load-bearing**: an *unbounded* `EntityList.entities` made the enrich step fail ~56 chunks on the 10-K's dense financial tables — the model emitted a runaway entity list that ran past `max_tokens` and truncated the JSON ("Model output did not match the requested schema"), dropping the whole chunk. Bounding the list (xgrammar enforces maxItems) + raising the enrich per-call `max_tokens` to `_ENRICH_MAX_TOKENS=3072` took it 56→4. NB this was the *real* fix; the chunker `MAX_CHUNK_MULTIPLIER` cap (word-budget) is a no-op on word-light/char-heavy tables.
- **Chart-OCR output is LLM-readable markdown, not raw LaTeX.** Nemotron-Parse-v1.2 (the default chart-OCR backend) emits `\begin{tabular}{cc} **On Time 22** & **Late 8**\\ \end{tabular}` which the assess/answer LLMs cannot parse as structured data. The v7 fix (`chart_ocr_backend._normalize_latex_tabulars` + `_split_label_number_cells`) post-processes Nemotron output into markdown tables (multi-row) or key:value bullets (single-row chart summaries where each cell matches `<label> <number>`). When extending the chart-OCR backend with new models, keep emission in LLM-native markdown — pipe-tables, bullet lists, prose sentences. Raw LaTeX in chart-extracted blocks is a regression.
- **Chart-extracted blocks are visible to assess/answer/verify** (P3.3 v7, 2026-05-23). Earlier defenses (v3/v5/v6) stripped `[chart-extracted]...[/chart-extracted]` blocks from the chunks before rendering the assess/answer/verify prompts because raw LaTeX (~500+ chars per block) ate the `truncate(1200)/truncate(1800)` budget. With v7's compact markdown emission (~50-150 chars per block), strips are no longer needed and would actively block chart-content answering. Do not re-introduce strips in `agents/answering.py:assess`, `answer`, or `verify` — chart blocks should flow through to the LLM. The FTS-side strip in `index/fts_store.py` (P3.3 v3 defense) is retained: BM25 keyword search on chart-block content adds noise without helping retrieval recall.
- **Chunker treats `# H1` lines INSIDE `[chart-extracted]` blocks as inert** (P3.3 v7 chunker fix, 2026-05-23). Nemotron-Parse emits H1 prefixes for chart-figure-section labels (e.g. `# Minimal lead-time`, `# Inter-operability`) which look like document headings to a naive regex. `core/text.py::chart_extracted_spans` + `is_inside_any_span` are the helpers; `index/chunker.py::_split_into_sections` and `_heading_path_at` filter heading matches inside those spans. The fix recovered slide-decks Q31 ("4 design principles") + Q18 ("NVLink C2C 900 GB/s" via chunker reflow) + annual-report Q03 ("Data Center revenue $193.737B"). When extending chart-OCR or the chunker, preserve this contract — pinned by `tests/unit/test_chunker_chart_aware.py::test_h1_inside_chart_block_does_not_split_section`.
- **The verify node filters phantom claim-indices** (P3.3 v7 verify-fix, 2026-05-23). The verifier LLM can emit indices > n-1 when distracted by chunk content not in the draft (xgrammar `max_length=n` bounds list length but not index values). `agents/answering.py:verify` filters to `[0, n-1]` and conservatively treats indices missing from BOTH `grounded` and `ungrounded` as ungrounded. Pinned by `tests/integration/test_answering_with_fakes.py::test_verify_filters_phantom_indices` + `test_verify_missing_index_treated_as_ungrounded`.
- **The relevance gate refuses grounded-but-non-responsive answers** (2026-05-26, `agents/answering.py::assess_relevance` + `prompts/assess_relevance/v1.md`). Grounding (verify) confirms a claim is supported by its chunk, but a grounded claim can still answer a RELATED-BUT-DIFFERENT question than asked. A node runs after `verify` on the grounded path, before `compose` (`verify --grounded--> assess_relevance --> compose | refuse`): `RelevanceAssessment {responsive, reason}` asks whether the verified draft addresses the SPECIFIC question; a non-responsive verdict routes to `refuse`. **Deliberately conservative** — the prompt defaults to responsive; premise-rejections ("there is no such option") and short/partial on-topic answers stay responsive — so it removes ONLY clear question/answer topic mismatches, not legitimate answers. Motivating case slide-decks-30: the CUDA deck's "C++/Python abstractions for tensor cores" grounds a library-usage claim the agent passed off as the answer to "which language writes CUDA *kernels*" (grounded, but a conflation). GPU-validated multi-run (slide-decks-30 refuses reliably; no over-refusal on clear-answer corpora). **Load-bearing lesson:** tuning the `assess_sufficiency` prompt for this was WHACK-A-MOLE — the apparent v1-vs-v2 regressions were **eval non-determinism** (borderline counterfactuals flip run-to-run under the agent's BF16/AWQ greedy decode; a v1-revert showed the SAME flips). `refusal_cf=1.0` is a single-run metric — **measure borderline-gate changes multi-run**. The gate is a SECOND orthogonal filter (lowers the conflation flip rate), NOT a determinism fix; it does NOT catch cross-doc SCOPE conflations (cr350-diag-12 answered "firewall-diagram VLAN range" from semaine-4's VLAN content — responsive but wrong source; that's multi-doc disambiguation, **now fixed deterministically by the artifact→doc re-scope below**). Pinned by `test_answering_with_fakes.py::test_non_responsive_grounded_answer_is_refused`; the 4 graph-exercising test fakes default `RelevanceAssessment`→responsive.
- **`route_after_verify` ships the GROUNDED SUBSET on a partial-grounded draft** (2026-05-26, the compound-question over-refusal fix). Verification grounds CLAIMS individually, so a draft can come back MIXED — some grounded, some not (e.g. a compound question whose groundable half the corpus supports and whose other half it doesn't). The router used to be all-or-nothing: `all_grounded → compose`, else regenerate-then-**refuse** — so a regen that couldn't ground *everything* discarded the whole answer (incl. the groundable half). Now: still regenerate while budget+attempts remain (the answer node gets the ungrounded-claim feedback and tries to ground the rest); but once **exhausted (or over budget)**, if a NON-EMPTY grounded subset survives, route to `compose` (→ via `assess_relevance`) to ship it — `compose` drops the ungrounded claims (its existing defense-in-depth) AND **rebuilds the summary from the surviving claims** (`summary = " ".join(c.claim …)` when any claim was dropped) so no ungrounded assertion leaks into the headline. **Only a ZERO-grounded verdict refuses**, so counterfactuals are unaffected (`refusal_cf` preserved — GPU-validated multi-run on the counterfactual corpora). HARD-gate-safe by construction: ships only verified-grounded claims, vetted by the (already-grounded-subset-judging) relevance gate; worst case is a relevance miss (a grounded-but-off-topic subset), never a hallucination. The answer-node "drop ungroundable claims" prompt feedback is NOT enough alone — the LLM keeps trying to answer an explicitly-asked sub-question (observed live), which is why the fix is deterministic in the router, not the prompt. Helper `_has_grounded_claims` mirrors compose's surviving-claims test (valid index in range). Kill-switch `agents.partial_grounded_answers` (env `MEMEX_AGENTS__PARTIAL_GROUNDED_ANSWERS=false`, read fail-open in `answer_query` → `AnswerState.allow_partial_grounded`; the router stays pure, reading state). Pinned by `tests/unit/test_answer_routing.py` (the routing matrix + `_has_grounded_claims` phantom-index handling) + `test_answering_with_fakes.py` (partial ship drops the ungrounded claim + rebuilds the summary; zero-grounded still refuses; kill-switch reverts to all-or-nothing; `test_verify_missing_index_treated_as_ungrounded` now asserts the omitted claim is *dropped*, not whole-answer-refused).
- **A named artifact deterministically re-scopes retrieval to its document(s)** (#256, 2026-05-26, `agents/artifact_scope.py` + `agents/answering.py::resolve_artifact_scope`, spec `docs/specs/artifact-scope.md`). When a query NAMES a specific artifact ("le diagramme de coupe-feu", "the Gantt chart"), a node between `retrieve` and `expand_graph` resolves it to the doc(s) it lives in and **REPLACES** the candidate pool with `hybrid_search_in_docs(query, scope_docs, k=50)` — the named artifact is an automatic doc-selection. Two PURE stages (`detect_artifact_reference` regex EN+FR → `resolve_scope` per-token BM25), **no LLM** (the determinism mandate — an earlier LLM `assess_relevance` source-scope clause was validated ineffective and reverted, Qwen3-8B gave 0 non-responsive verdicts). For cr350-diag-12 this makes the refusal DETERMINISTIC by construction: the re-scope removes semaine-4's VLAN chunk from the pool before the LLM sees it, so there's no VLAN evidence to (mis)answer from regardless of greedy sampling. **The positional qualifier rule is load-bearing**: FR `diagramme de <tail>` captures the tail AFTER the connector ({coupe,feu}) and the data term precedes the noun (so 'vlan' is excluded for diag-12), while the near-twin "diagramme de configuration VLAN" INCLUDES vlan → scopes to the VLAN deck (answers). **The single-token specificity gate is also load-bearing**: a LONE qualifier token only scopes when distinctive (title hit OR sole-doc), else no-scope — this blocks the slide-decks-04 "TSMC chart" mis-scope (the CUDA deck's in-chart "tsmc" is FTS-stripped, so the bare token dominantly matches the 10-K's prose mentions → would false-refuse an ANS query); multi-token qualifiers (where every #256 fix lives) are exempt. **Conservative + fail-open + HARD-gate-safe by construction**: no artifact / no confident resolution / kill-switch (`MEMEX_AGENTS__ARTIFACT_SCOPE_ENABLED=false`) / any store error all leave candidates untouched (the full-corpus path); the node can only NARROW retrieval, never add a chunk or relax a gate, so the worst case is a conservative false-refuse on a mis-resolved ANS query, never a hallucination or wrongly-answered counterfactual. `expand_graph` short-circuits while a scope is active (else it would re-admit out-of-scope chunks). Pinned by `tests/unit/test_artifact_scope.py` (detection/resolution tables, the diag-12-vs-img-01 discriminator, the single-token gate, N=50 determinism) + `test_answering_with_fakes.py` (re-scope refuses wrong-source / near-twin answers / no-artifact no-op / fail-open / kill-switch / expand_graph-skip). The lazy `FTSStore.open` inside the resolver follows the documented `agents/ → index/` lazy-store edge (same as `expand_graph`/`query_tables`). **The resolved scope is surfaced on `FinalResponse.artifact_scope_doc_ids`** (populated in `compose` + `refuse` from `state.artifact_scope_doc_ids`; `[]` on the full-corpus path) so the re-scope is auditable — on a refusal it explains WHY the pool was narrowed (ADR-0004, observable at every layer). HARD-gate-neutral (a derived observability field, never alters answered/claims/refusal); MCP/CLI auto-serialize it, and the webui answer panel renders a quiet "Scoped to …" note (`.ans-scope`). **The explicit doc-picker (2026-05-27) rides the SAME node:** `answer_query(scope_doc_ids=[...])` (the webui's `<details>` checklist → `/ask` Form list; MCP `ask`'s `scope_doc_ids`; CLI `--doc`) sets `AnswerState.scope_doc_ids`, which `resolve_artifact_scope` honors FIRST — scoping to exactly those docs (dedup + blank-strip) and TAKING PRECEDENCE over inference (no `detect_artifact_reference`, no FTS resolver). It writes the same `artifact_scope_doc_ids` (the *applied* scope), so the surfacing + the `expand_graph` short-circuit are shared; worst case is an empty scoped pool → clean refuse (HARD-gate-safe — only narrows). Pinned by the explicit-scope tests in `test_answering_with_fakes.py` (answers-from-pick / precedence-over-artifact / dedup / empty-scope-full-corpus / scoped-can't-answer-refuses / empty-pool-clean-refuse) + `test_webui.py` (picker renders, scope forwarded, "your selected" label) + `test_mcp_server.py`. Spec `docs/specs/artifact-scope.md`. **Saved scope sets (2026-05-27, `core/scope_sets.py`, spec `docs/specs/scope-sets.md`)** are the PERSISTENCE layer over the picker: a named `doc_ids` collection stored as a single atomically-written JSON at `vault/.memex/scope_sets.json` (mirrors `core/manifest.py`'s `mkstemp`→`fsync`→`os.replace`; **user-authored, so deliberately NOT in the `reindex_vault(force=True)` teardown allow-list** — a full rebuild preserves it). A set is purely a naming layer that resolves to `doc_ids` AT THE SURFACE and feeds the EXISTING `answer_query(scope_doc_ids=...)` path — **the agent never imports `scope_sets`** (no new agent coupling), and the same HARD-gate guarantee holds (a stale set whose docs were removed resolves to an empty pool → clean refuse). Surfaces: CLI `memex scope-set create|list|show|delete` + `memex ask --scope-set NAME`; MCP `ask(scope_set=)` (unknown name → `ConfigurationError`, never a silent full-corpus search) + a new `list_scope_sets` tool; webui `_scope_picker.html` saved-set bar (apply re-ticks the boxes server-side; `/ask` stays `scope_doc_ids`-only). `read_scope_sets` raises `VaultIntegrityError` on a corrupt store (loud at the management surface) while `resolve_scope_set_doc_ids` fails OPEN to `[]` (a corrupt file never breaks `ask`); name lookup is case/whitespace-insensitive (`normalize_set_name`), the set NAME is a JSON value never a path component (no traversal risk). Pinned by `tests/unit/test_scope_sets.py` (CRUD/upsert-preserves-created_at/dedup/validation/corrupt-raises-vs-resolve-fails-open/ordering-determinism) + `test_webui.py` (save→appears, apply→pre-checks, delete→removed) + `test_mcp_server.py` (scope_set unions doc_ids, unknown raises, `list_scope_sets`).
- **The answer node repairs corrupted citation chunk-ids** (2026-05-23, surfaced by the CR350 multi-doc eval). The answer LLM is shown full `docid#hash` chunk ids but occasionally drops the `docid#` prefix (bare hash) or flips a character. `agents/answering.py:_repair_claim_chunk_ids` snaps each emitted `source_chunk_id` back to a real reranked chunk_id — exact → suffix-match (bare hash) → bounded-Levenshtein fuzzy-match with a strict uniqueness guard; unresolved ids are left as dangling citations the verifier marks ungrounded. Runs in `answer` (before `verify`) so the grounding lookup (`chunk_by_id[source_chunk_id]`) and `compose`'s `used_chunks` reconstruction both see the corrected id. Pinned by `tests/unit/test_chunk_id_repair.py`. Don't move the repair after verify — verify depends on it.
- **The answer prompt treats markdown-table-row reading as literal** (P3.3 v7 Q09 fix, 2026-05-23). The answer/v3 prompt's "Tables and structured data are literal" rule clarifies that reading a row from a markdown table or a key-value bullet inside a `[chart-extracted]` block counts as a literal claim, not an inferential one. This mirrors `verify_grounding/v2`'s pre-existing rule and was added when chart-types Q09 (Gantt assignees) was false-refusing — the answer LLM was over-applying the No-substitute rule to clearly structured tables.
- **EmbeddingGemma is used with its native `task:`/`title:` prompts** (2026-05-25, `index/embed_prompts.py`). EmbeddingGemma is a prompt-trained ASYMMETRIC retriever; embedding bare is off-distribution. Queries embed via ST `prompt_name="query"` (`retrieve/hybrid.py::_embed_query` → `task: search result | query: {q}`); document chunks embed via a manual `f"title: {chunk_title(c)} | text: {c.text}"` wrapper (`index/pipeline.py::_embed_chunks`), where `chunk_title` = deepest `heading_path` else `document_title` else `"none"`. **Load-bearing invariant: the prompt wraps ONLY the transient embedding INPUT — `chunk.text`/`chunk_id`/the stored+retrieved chunk text are UNCHANGED**, so the prompt never reaches assess/answer/verify (no leak), chunk_ids stay stable (anchors valid), and it's pure-string (NO vLLM). Query+doc sides MUST flip together (a bi-encoder needs both in the matching space) — gated by one `native_prompts_enabled()` (`MEMEX_EMBED_NATIVE_PROMPTS`, default ON). An embed-recipe change is migrated via `IndexStage.embedding_recipe_version` (`_embed_recipe_version()`: `v1-gemma-prompts`/`v0`) OR'd into the `index_document` force-detection → flipping the toggle auto-forces a full re-embed on the next `reindex`. **Do NOT regress to bare `encode()`** — it's the model's documented misuse. Pinned by `tests/unit/test_embed_prompts.py` + `test_partial_reindex.py` (leak/chunk-id/recipe-bump). (This is the in-distribution lever the FAILED contextual-retrieval LLM-prefix experiment pointed to — don't confuse them: that prefix was a long off-distribution LLM sentence that broke the HARD gate; these are the model's short trained prompts.)
- **The PyMuPDF worker re-derives heading levels from font size** (2026-05-24, `pymupdf_worker.py`). pymupdf4llm 1.27.x detects heading lines correctly but its emitter collapses every one to `## `. `_heading_size_to_level` builds a doc-wide rounded-size→level map (body = most-frequent span size; larger distinct sizes rank descending into levels 1..6) and `_remap_heading_levels` rewrites each already-detected `#`-prefixed line's prefix from its real font size — skipping fenced code, leaving unmatched/no-tier headings as emitted. It **only changes the `#`-count**: never adds, removes, or moves a heading or a chunk (chunk boundaries + body content stay byte-identical apart from the prefix). Pinned by `tests/unit/test_heading_remap.py`. Don't reintroduce the flat-`##` emission, and don't move the remap before `_clean_pymupdf_markdown` (it expects the cleaned `<br>`/marker-stripped text). Known limitation: on slide decks (erratic per-slide fonts) the size heuristic can mis-level a title slide — acceptable (still recovers hierarchy, loses no content), but don't tune the heuristic against a slide deck at the cost of the born-digital prose fixtures (which hit structural-F1 ~1.0). **Misdetected-heading DEMOTE (2026-05-25):** `_remap_heading_levels` also demotes a heading line to a plain paragraph when its matched span font is body-size-or-smaller (not a heading tier) AND the text reads as prose (`_looks_like_prose_heading`, ported verbatim from the Docling worker's `_demote_misdetected_headers` — >15 words, or ≥4 words ending in `.!?`). The font-size gate makes it strictly safer than Docling's markdown-only fallback: a large-font heading ending in a period is never demoted, only a body-font line pymupdf4llm over-flagged. A heading with no span match is left as emitted (font unknown → conservative). **`<br>`-in-table fix (2026-05-25):** `_normalise_breaks` is table-aware — a `<br>` is an in-cell line wrap inside a GFM pipe row, so within a pipe row it collapses to a single SPACE (not `\n\n`, which would shatter the row across lines and destroy the table); outside pipe rows the paragraph-break behaviour for chart/picture-text runs is unchanged. Both pinned by `tests/unit/test_heading_remap.py`.
- **The Docling worker recovers heading levels from bbox height** (2026-05-24, `docling_worker.py`). Docling's PDF reading-order model leaves every `SectionHeaderItem` at `level=1`, so the serializer (`num_hashes = item.level + 1`) collapses all headings to `## `. `_recover_heading_levels` runs **before `export_to_markdown()`** (wired right after `doc = result.document`), re-deriving each header's level from a font-size proxy — provenance `bbox.height`, since Docling exposes no font size — by ranking the distinct header heights **among themselves** (largest → level 1, bucketed to 0.5 pt, capped at 5 → `######`) and writing `item.level` back in place. It's duck-typed (label value `"section_header"` + writable `.level`) so it needs no docling import and is unit-testable with fakes (`tests/unit/test_docling_heading_levels.py`). Two contracts to preserve: (1) rank headers **among themselves**, not against body text — uniform slide-titles must stay flat (peers stay peers; don't reintroduce a body baseline that mis-promotes a title slide); (2) it operates on structured items **before** chart-OCR stitches `[chart-extracted]` text in, so it needs NO chart-block/fence defense (unlike the PyMuPDF markdown post-process) — keep it pre-export. This is the Docling analogue of [`pymupdf_worker._heading_size_to_level`]. Known limitation: a multi-line heading's taller bbox over-ranks (pinned). The fix helps well-structured docs and is no-op-ish/noisy on slide decks, so migrate vault docs to it only when a re-parse measurably improves them. **Companion mis-DETECTION fix** (`_demote_misdetected_headers`, same module): Docling also mis-*detects* body sentences as `SectionHeaderItem`s on dense docs. Because `SectionHeaderItem` subclasses `TextItem` and the serializer dispatches headings by `isinstance` (not `label`), the fix reassigns a prose-like header's `__class__` to `TextItem` **before export** (the real `TextItem` is injected as `text_item_cls` so the fn stays duck-typed/testable) → it serialises as a paragraph natively, fixing the document model (chunking + `heading_path` see a paragraph). The discriminating signal is **textual, not bbox-height** (height is too noisy for detection on slide decks): demote if the text ends in terminal punctuation with ≥4 words (guarding labels like "Item 1.") or runs >15 words — see `_looks_like_prose_heading`. The `__class__` swap is wrapped defensively; the markdown post-process `_demote_prose_headings` is retained as a **fallback** for anything that slips past. Wiring order in `_convert_to_payload`: re-level → reclassify-prose → export → markdown-fallback.
- **VLM escalation fires on image-area dominance, NOT Docling text-confidence** (2026-05-25, `parse/pipeline.py::_route_and_escalate` + `docling_worker.py`). The confidence trigger was dead in production: `DoclingDocument.pages` is a `dict[int, PageItem]` (iterating yields int KEYS, not items) and a `PageItem` has no `.confidence` (it lives in a doc-level `ConfidenceReport`, NaN unless a pipeline option populates it), so `getattr(p, "confidence", 1.0)` always returned 1.0 → `confidence < threshold` never fired, AND per-page markdown came out empty (a `PageItem` has no exporter). The worker now iterates `pages.values()`, takes per-page markdown via `doc.export_to_markdown(page_no=N)`, and computes a per-page **`image_fraction`** (Σ figure-bbox-area / page-area from `PageItem.size`, via the pure helper `_image_fraction_by_page`) carried on `DoclingPageOutput.image_fraction`. `_route_and_escalate` escalates a page when ANY of three arms fire: `confidence < vlm_confidence_threshold` **OR** `image_fraction >= vlm_image_area_threshold` (default **0.20**) **OR** it carries a figure Docling's PictureClassifier labels a diagram type in `vlm_diagram_classes` (`flow_chart`/`engineering_drawing`/`screenshot…`) above `vlm_diagram_min_confidence` (0.5) and ≥ `_MIN_DIAGRAM_AREA_SQPT` (20000, via the pure helper `_diagram_pages`). The image-area arm is the dominant real signal (diagram pages Docling reads "confidently" while losing the figure content; calibrated on real CR350 diagrams 0.24–0.38). The **classification arm** (2026-05-25, added during the vault-wide VLM audit) catches a SMALL flow chart / engineering drawing / screenshot on a TEXT-dominant page — below the 0.20 area bar AND excluded by the chart-OCR pass (which only extracts data charts, not diagrams), so without it those figures fall through both passes. The audit found ~57 such figures stranded across the 6 CR350 lectures; the arm recovered 51 of 53 flowcharts/engineering-drawings + all 4 screenshots. - **Table-RAG Phase 2 — the text-to-SQL tool reuses grounding and holds the HARD gate by construction** (2026-05-24). Four invariants future contributors MUST preserve: **(a)** a SQL answer is injected as a **synthetic `Chunk`** into `state.reranked` (chunk_id `<doc_id>#sql0001`) by the `query_tables` node (between `rerank` and `assess`) — the existing assess/answer/verify/compose machinery then cites it like any other chunk. Do NOT invent a new grounding path or a LangGraph `ToolNode`; the synthetic-chunk seam is the whole point. **(b)** The **row-vs-aggregate fabrication boundary** is load-bearing: a hallucination is a value the doc doesn't contain. Row-returning SQL ships **verbatim document cells** (safe to inject). Aggregate SQL ships a **new number**, so it's injected ONLY when `agents/table_sql.py::_recompute_aggregate` (an independent Python recompute over the original cell text) agrees — otherwise the node is a no-op and the agent refuses. Never inject an unverified aggregate; that breaks the `refusal_cf=1.0` / zero-hallucination HARD gate. **(c)** `_compute_schemas` is the **single source of truth** for sanitized SQL identifiers — the `generate_table_sql` prompt AND `_load_tables` must consume the *same* schema, and the prompt must NEVER show unsanitized column/table names (a name mismatch makes the model emit SQL that can't execute). **(d)** `tables.sqlite` (`~/.memex/vault/.memex/tables.sqlite`) is **regenerable derived state** (ADR-0003) built in `index_document` via `index/table_store.py::TableStore.extract_tables` (reuses the Phase-1 GFM parser + header-sanity gate — well-formed tables only); it's in the `reindex --force` teardown. `query_tables` opening `TableStore` lazily inside the node follows the already-documented `agents/ → index/` lazy-store-open edge (same as `expand_graph`/`GraphStore`).

## Errors

- Every raise uses a `MemexError` subclass from `core/errors.py`. Subclasses today: `InsufficientVRAMError`, `ParseConfidenceTooLow`, `RetrievalEmpty`, `VaultIntegrityError`, `IndexOutOfSync`, `ConfigurationError`, `StaleDocumentError`, `AnswerStateInvariantError`, `ModelCallError`, `ScopeSetError`. Module-local subclasses are fine as long as they inherit from `MemexError` — current ones: `CircuitBreakerOpen` (core/breakers.py); `ModelNotConfigured` (models/registry.py); `VLMUnavailable`, `PDFRenderError` (parse/vlm_backend.py); `ChartOCRUnavailable`, `PDFFigureRenderError` (parse/chart_ocr_backend.py); `DoclingUnavailable`, `DoclingTimeout`, `DoclingCrashed`, `SandboxLoadFailed` (parse/docling_backend.py); `PyMuPDFUnavailable`, `PyMuPDFTimeout`, `PyMuPDFCrashed` (parse/pymupdf_backend.py); `DaemonAlreadyRunning`, `DaemonStartTimeout` (daemon/supervisor.py).
- Every raise carries a `context: dict` with the values a user needs to act on the error.
- Recoverable errors set `recoverable=True` so the pipeline knows to resume on retry.
- **Narrow `except` clauses.** Never `except BaseException` (would swallow `CancelledError`, `KeyboardInterrupt`, `SystemExit`); never `except Exception` unless you re-raise the cancellation cases above explicitly. When wrapping a third-party SDK exception, check the module via `type(e).__module__.startswith(...)` rather than catching the broad base class.

## Async / sync

- **Async**: filesystem I/O, model calls, database operations, HTTP, MCP transport.
- **Sync**: token parsing, formatting, chunker, pure transformations.
- CPU-heavy sync work called from async code goes through `asyncio.to_thread` (`models/registry.py` does this for sentence-transformers `encode`; `index/fts_store.py` for sync SQLite).
- **Per-resource locking** is `asyncio.Lock` for stores serving async callers (`index/fts_store.py::FTSStore._lock` gates multi-statement writes; `vault/store.py::_DOC_LOCKS` gates per-doc write paths) and `threading.Lock` for state that crosses both sync and async callers (`agents/answering.py::_COMPILED_GRAPH_LOCK` gates the lazy graph compile). Don't mix the two — pick by who the callers are. The `models/registry.py::_locks` per-model dict + the breaker's lock are the canonical patterns to copy.

## Logging

structlog. Bind once per run scope at the entry point (`bind_run_context(correlation_id, ...)`), bind node/function scope locally (`log = logger.bind(node="rerank")`), emit `log.info("event", k=v)`. **Never** `extra={...}` (lost), **never** f-strings in event names (kills aggregation in Langfuse).

## CUDA

ADR-0006 settles it. The summary:

- **bf16** is the dtype across the stack on Ada. Embedder, reranker, VLM, and chart-OCR all use explicit `torch_dtype=torch.bfloat16`. (FP16 is forbidden for EmbeddingGemma — its activations don't support it.)
- **FA2** for the VLM (`attn_implementation="flash_attention_2"`). FA3 is unavailable on sm_89.
- **`device_map={"": "cuda:0"}`** — deterministic single-GPU placement, not `"auto"`.
- **Retrieval device override (2026-05-27):** `ModelSettings.{embedder,reranker}_device` (`"cuda"` default, or `"cpu"`) places the embedder/reranker on CPU (fp32 via `registry._retrieval_dtype`) to free GPU VRAM for a full-util orchestrator KV cache on a single 12 GB card. `_do_load` passes the device to `_load_embedder`/`_load_reranker`/`_load_reranker_qwen3`; the retrieval path already follows each model's own device (`rerank.py` reads `next(model.parameters()).device`), so no other change. `bootstrap._estimated_vram_gb` (the now-pure, testable VRAM estimate) excludes a CPU-placed model. Trade-off = ~20 s CPU rerank latency vs a squeezed KV at lower util (ADR-0006 §2 amendment). Pinned by `tests/unit/test_retrieval_device.py`.
- **Co-residence MODES are a policy layer over those device knobs (2026-05-27, ADR-0007, `core/resources.py`).** `ModelSettings.co_residence_mode` (`fast`/`full`/`gpu_only`/`manual`, default `manual`) resolves via the PURE `resolve_profile(mode, *, total_vram_gb, embedder_device, reranker_device) -> ResourceProfile` — the SINGLE place the VRAM tradeoff is encoded, and the seam a future dynamic VRAM manager replaces (compute the profile from live free-VRAM) without touching callers. Consumers: `registry._do_load` calls `effective_devices(...)` (a curated mode OVERRIDES the explicit device knobs; `manual` honors them); `bootstrap._estimated_vram_gb` uses the effective devices; the daemon (`daemon.supervisor.restart(gpu_fraction=, max_model_len=)`) launches vLLM with the profile's `orchestrator_gpu_fraction`/`orchestrator_max_model_len` (via the `MEMEX_VLLM_*` env the serve script reads); the CLI (`memex mode show|set`, `memex daemon restart`); the webui (`/resources` page + the header `active_mode_label` jinja global). `manual` is the default → fully backward-compatible. `core/resources.py` is PURE (no `config` import → no cycle; `config` imports IT for the `CoResidenceMode` Literal). `core/config.py::config_toml_path()` is exposed for `memex mode set`'s persist instruction. Pinned by `tests/unit/test_resources.py` + the registry-mode + webui `/resources` + daemon-restart tests. **`full` mode is a CAPABILITY: it raises `max_model_len` (~24,576) for whole-document `agents/synthesize.py` synthesis** (`memex summarize`, the free-form baseline). **Synthesis grounding contract (forthcoming, Phase B):** the baseline is free-form + ungated and degrades to a clean refusal on the truncation failure (`ModelCallError` → refusal); the production doc-type-aware structured summarizer must use a `maxItems`-bounded schema (xgrammar enforces list bounds, NOT string `maxLength`) + map-reduce + per-point grounding (its own ADR/spec).
- **`AutoModelForImageTextToText`** for the VLM, not `AutoModelForCausalLM`.
- **`cli/bootstrap.py:_configure_cuda`** runs once at startup: CUDA assert + TF32 + `cudnn.benchmark` + `set_per_process_memory_fraction`. Tests bypass it.

## When adding a new module

1. Check the architectural blueprint — module signatures are already designed in `docs/IMPLEMENTATION-PLAN.md` §1.
2. Update `src/memex/<module>/__init__.py` to re-export the public surface.
3. Add an integration test under `tests/integration/`. Fake every external (`monkeypatch.setattr`).
