# `src/memex/` — Backend conventions

Python 3.12+, pyright `--strict` against `src/memex/`, ruff for lint + format. The full engineering manual is [`docs/GUIDELINES.md`](../../docs/GUIDELINES.md); this is the cheat-sheet.

## Module boundaries

`core/` has no Memex deps — everything else may import from it. Import direction otherwise:

```
agents/ → models/ + observability/ + prompts/ + retrieve/ + index/ + core/
retrieve/ → index/ + models/ + core/
index/ → models/ + vault/ + core/
parse/ → models/ + vault/ + core/ + observability/
enrich/ → models/ + index/ + prompts/ + vault/ + core/
ingest/ → vault/ + core/
mcp/ → agents/ + retrieve/ + vault/ + core/
webui/ → agents/ + vault/ + core/    (+ index/graph_store as a test seam; + index.retitle_document as a write path; + daemon + models.registry for the live mode hot-switch; + parse.pdf_render for the source-preview rasteriser; + retrieve.entity_overview for the /entity discovery view)
cli/ → everything
daemon/ → core/                       (vLLM lifecycle is config-driven)
```

A module **may not** import a private symbol (`_foo`) from another module. If something needs to be shared, it gets a public name.

The `agents/ → index/` edge is the lazy-store-open pattern: `agents/answering.py`'s `expand_graph` opens `GraphStore` and `query_tables` opens `TableStore` (Table-RAG Phase 2) inside the node, in a `try/finally` — the agent owns no threaded store handle. Same precedent as `webui/`'s lazy `GraphStore` open. The stores' public surface only (`GraphStore`, `TableStore`, `query_doc_tables`), never private symbols.

**`expand_graph` is DEFAULT-OFF (2026-05-28, `MEMEX_AGENTS__GRAPH_EXPANSION_ENABLED`).** A microscope audit ([[db-audit-2026-05-28]]) proved 1-hop "shares-an-entity" expansion does real work for ZERO answer impact at this corpus scale: an A/B was byte-identical on both cross-doc corpora, and a per-query trace showed the node adds 2-12 neighbour chunks of which the reranker cites exactly 0 — the neighbours are linked by GENERIC entities (`neighbors()` is unranked) and hybrid k=50 already has near-total recall at 47 docs, so there's no missed doc to recover. It's an env opt-in for a large entity-rich vault; the `answer_query` param is ANDed with the setting. The **graph store is kept** for its on-mission consumer: **`GraphStore.related_documents(doc_id)`** — the "explore connections" discovery surface (CLI `memex related`, MCP `related_documents`, webui doc-view "Related documents"). Unlike `neighbors()`, it ranks neighbours by shared-entity SPECIFICITY (Σ IDF over shared entities, excluding entities mentioned by >60% of docs as generic noise) via the pure, unit-tested `_rank_related_documents` — so a doc sharing one rare concept outranks one sharing five generic terms. **The graph-grouping INVERSE — `GraphStore.related_bridges(doc_id)` (2026-05-29, `b48f8b2`, the webui `/graph` "Bridges" view)** — consumes the SAME rows (via a shared `_fetch_shared_entity_rows`) but groups related docs UNDER each shared ENTITY (the bridging concept) instead of under each doc, via the pure, unit-tested `_rank_bridges` → `DocumentBridge{entity, kind, doc_count, strength, docs}`. Bridge `strength = mean(IDF×kind_weight) × ln(1 + doc_count)`: per-edge specificity dominates, fan-out enters LOGARITHMICALLY — a *linear* × fan-out (the first cut) made breadth win and surfaced exactly the generic networking terms (`network`/`IP`/`IPv4`) the view should bury; the log damping promotes specific concepts (`OSI`/`ACL`/`ARP`/`DHCP`). Webui-only discovery (not on `FinalResponse`) ⇒ HARD-gate-neutral; spec `docs/specs/graph-discovery.md`. NB the (opt-in) `expand_graph` still uses the OLD unranked `neighbors()`, not `related_documents`; wiring the specificity ranking into expansion is a documented future hook that only pays off at large-corpus scale (where retrieval misses docs). **The graph's SECOND discovery consumer is entity-centric retrieval (2026-05-28, ADR-0011 build-out, spec `docs/specs/graph-discovery.md`): `GraphStore.entity_profile(name)`** resolves a free-text name (case-insensitive, aggregating across kinds) → its identity (kind(s) + true `doc_count`), the authoritative MENTIONS doc set (capped), and the co-occurring concept neighbourhood via the pure `_rank_co_occurring` (`shared_docs × ln(N/df) × kind_weight`; reuses `_ENTITY_KIND_WEIGHT` + `_RELATED_GENERIC_ENTITY_DF_FRACTION` — the shared specificity filter; the `shared_docs` multiplier is the only new term). The orchestrator **`retrieve/entity.py::entity_overview`** (the `retrieve/ → index/` lazy-store edge, mirrors `related_documents`' callers + ImportError fail-open) composes that with `FTSStore.search_in_docs` (scoped to the mention docs when resolved) / `FTSStore.search` (whole-corpus fallback when unresolved or graph-absent). Surfaces: CLI `memex entity`, MCP `entity_overview`, webui `/entity`. Read-only ⇒ HARD-gate-neutral. **Cypher contract (load-bearing, caught by the opt-in real-ryugraph test):** a `RETURN DISTINCT … ORDER BY <expr>` must `ORDER BY` the PROJECTED ALIAS, not `d.<prop>` — after a `DISTINCT` projection ryugraph drops the original binding from scope. Pinned by `tests/unit/test_entity_profile.py` (pure rank) + `tests/integration/test_entity_overview.py` (orchestrator fakes) + `tests/integration/test_entity_profile.py` (live Cypher, `importorskip`). **`entity_profile` also bridges ACRONYM ↔ EXPANSION (2026-05-28, the resolution deepening):** `DNS` and `Domain Name System` are separate entity_ids, so it computes `EntityProfile.suggestions` (`EntitySuggestion{name,kind,doc_count,relation}`) on BOTH the resolved ("Also see") and unresolved ("Did you mean?") paths — **SUGGEST-only, never an identity merge** (the exact-match `doc_count`/`matched_names`/passages are unchanged; a merge of an ambiguous initialism would assert a false identity). The match is **initialism**, NOT substring CONTAINS (rejected: noisy for popular acronyms, useless for rare): pure `index/initialism.py` (`derive_initialism` = first unicode-alnum char per significant word skipping EN+FR connectors; `looks_like_acronym`; `initialism_matches`). Two directions in `entity_profile`: acronym query → a bounded entity-name scan (only when `looks_like_acronym`); multi-word query → derive its initialism + one exact-name probe. The pure `_gate_suggestions` is conservative: **collision-drop** (≥2 DISTINCT names → ambiguous → no-op, the #256 rule), generic + self exclusion, and a **doc-count floor (`_MIN_SUGGESTION_DOC_COUNT`=2)** that kills cross-domain initialism FALSE-FRIENDS (live: `STP` → the 10-K's 1-doc "Short-term portion"). **The residual `STP` gap is NER, not resolution** — the graph has no `STP`/`Spanning Tree Protocol` entity to bridge to (enrich stored `spanning`), so `STP` stays the honest FTS fallback with 0 suggestions; the root-cause fix — better entity extraction upstream — SHIPPED 2026-05-29 as the OTTER NER swap (ADR-0012, [[bert-ner-enrich-scope-2026-05-28]]; see the enrich-backend rule under Type discipline). Pinned by `tests/unit/test_initialism.py` + the bridge cases in `test_entity_profile.py` / `test_entity_overview.py`. **The co-occurring NOISE filter (2026-05-28, `AgentsSettings` → `_cooccurring_min_shared_docs`, FAIL-OPENS to the default outside bootstrap):** `cooccurring_min_shared_docs` (default 2; `_rank_co_occurring` only) is a neighbourhood floor that drops single-doc co-mentions (~69% of the real noise — ports/sizes at `shared_docs=1`). It's corpus-AGNOSTIC + structural (zero per-corpus tuning) → it scales to any vault. **The curated by-NAME `entity_stopwords` list was REMOVED 2026-05-29** (with `_normalize_stopwords` + the `stopwords` param on both rankers + the `NoDecode` import): a hand-curated per-corpus name list — one user's `CR350` course code — doesn't generalise to a local-first app run on arbitrary corpora, and the [[bert-ner-enrich-scope-2026-05-28]] OTTER NER backend (now the live enrich entity extractor) types entities cleanly UPSTREAM, so it no longer earned its keep. Don't reintroduce a curated name list; fix entity noise at the extractor. Pinned by the floor cases in `test_entity_profile.py` (unit + real-graph) + `test_related_documents.py`.

The single deliberate exception is `webui/app.py` re-exporting `GraphStore` from `memex.index.graph_store` at module top — `tests/integration/test_webui.py` monkeypatches `memex.webui.app.GraphStore.open`, which only works if `GraphStore` lives at the module level. The route handler runs the open lazily and falls back gracefully when ryugraph isn't installed.

## Type discipline

- **`src/memex` is pyright `--strict` clean (0 errors, 0 warnings).** Keep it that way — `uv run pyright` is a gate.
- **Untyped third-party libs get local stubs, not silence.** Libraries that ship no usable types (langgraph, lancedb, pypdfium2, pyseccomp, …) have minimal `.pyi` stubs under `stubs/` (wired via `stubPath`), covering only the surface Memex uses — see `stubs/README.md`. For libs that ship a partial `py.typed` (torch, transformers, openai, typer), don't shadow them with a competing stub; fix at the call site with precise annotations / `cast()` / a single typed wrapper (e.g. `registry._from_pretrained`, `registry._bf16`). `# type: ignore[rule]` is a last resort and always carries a trailing `# reason`. A dynamic `pydantic.create_model(...)` should pass `__base__=TheStaticModel` so pyright keeps the field types.
- **No untyped `Any`.** If you need it, add a one-line comment explaining why.
- **Pydantic models cross module boundaries.** Dicts and tuples are module-internal only. Shared types live in `core/types.py`.
- **Node returns use `TypedDict`.** See `agents/answering.py:AnswerStateUpdate` — `total=False` catches state-key typos at type-check time.
- **`complete_structured` is generic over schema.** `tuple[T, int]` where `T = TypeVar("T", bound=BaseModel)`. Don't break that.
- **Bound LLM-emit `str` fields with `max_length=N`.** xgrammar enforces the bound at the JSON-schema grammar level, so the model cannot emit a runaway string that would trip `max_tokens` mid-emission and crash JSON validation. Established by the v6 fix to `SufficiencyAssessment.reason` (was unbounded → 2000-char ramble on counterfactual queries → eval crash) and extended to `DraftAnswer.summary`, `CitedClaim.claim`, `VerificationResult.ungrounded_reasons` items, `ExtractedEntity.name`, `ExtractedEntity.span_text`. Also cap `list[T]` LLM-emit fields with `max_length=N` (e.g., `DraftAnswer.claims` at 20; `EntityList.entities` + `CitationList.citations` at 24). When adding a new structured-output schema, audit every `str` and `list[...]` field for an explicit bound. **The entity/citation list bounds (2026-05-24) are load-bearing**: an *unbounded* `EntityList.entities` made the enrich step fail ~56 chunks on the 10-K's dense financial tables — the model emitted a runaway entity list that ran past `max_tokens` and truncated the JSON ("Model output did not match the requested schema"), dropping the whole chunk. Bounding the list (xgrammar enforces maxItems) + raising the enrich per-call `max_tokens` to `_ENRICH_MAX_TOKENS=3072` took it 56→4. NB this was the *real* fix; the chunker `MAX_CHUNK_MULTIPLIER` cap (word-budget) is a no-op on word-light/char-heavy tables.
- **Chart-OCR output is LLM-readable markdown, not raw LaTeX.** Nemotron-Parse-v1.2 (the default chart-OCR backend) emits `\begin{tabular}{cc} **On Time 22** & **Late 8**\\ \end{tabular}` which the assess/answer LLMs cannot parse as structured data. The v7 fix (`chart_ocr_backend._normalize_latex_tabulars` + `_split_label_number_cells`) post-processes Nemotron output into markdown tables (multi-row) or key:value bullets (single-row chart summaries where each cell matches `<label> <number>`). When extending the chart-OCR backend with new models, keep emission in LLM-native markdown — pipe-tables, bullet lists, prose sentences. Raw LaTeX in chart-extracted blocks is a regression.
- **Chart-extracted blocks are visible to assess/answer/verify** (P3.3 v7, 2026-05-23). Earlier defenses (v3/v5/v6) stripped `[chart-extracted]...[/chart-extracted]` blocks from the chunks before rendering the assess/answer/verify prompts because raw LaTeX (~500+ chars per block) ate the `truncate(1200)/truncate(1800)` budget. With v7's compact markdown emission (~50-150 chars per block), strips are no longer needed and would actively block chart-content answering. Do not re-introduce strips in `agents/answering.py:assess`, `answer`, or `verify` — chart blocks should flow through to the LLM. The FTS-side strip in `index/fts_store.py` (P3.3 v3 defense) is retained: BM25 keyword search on chart-block content adds noise without helping retrieval recall.
- **Chunker treats `# H1` lines INSIDE `[chart-extracted]` blocks as inert** (P3.3 v7 chunker fix, 2026-05-23). Nemotron-Parse emits H1 prefixes for chart-figure-section labels (e.g. `# Minimal lead-time`, `# Inter-operability`) which look like document headings to a naive regex. `core/text.py::chart_extracted_spans` + `is_inside_any_span` are the helpers; `index/chunker.py::_split_into_sections` and `_heading_path_at` filter heading matches inside those spans. The fix recovered slide-decks Q31 ("4 design principles") + Q18 ("NVLink C2C 900 GB/s" via chunker reflow) + annual-report Q03 ("Data Center revenue $193.737B"). When extending chart-OCR or the chunker, preserve this contract — pinned by `tests/unit/test_chunker_chart_aware.py::test_h1_inside_chart_block_does_not_split_section`.
- **The verify node filters phantom claim-indices** (P3.3 v7 verify-fix, 2026-05-23). The verifier LLM can emit indices > n-1 when distracted by chunk content not in the draft (xgrammar `max_length=n` bounds list length but not index values). `agents/answering.py:verify` filters to `[0, n-1]` and conservatively treats indices missing from BOTH `grounded` and `ungrounded` as ungrounded. Pinned by `tests/integration/test_answering_with_fakes.py::test_verify_filters_phantom_indices` + `test_verify_missing_index_treated_as_ungrounded`.
- **The relevance gate refuses grounded-but-non-responsive answers** (2026-05-26, `agents/answering.py::assess_relevance` + `prompts/assess_relevance/v1.md`). Grounding (verify) confirms a claim is supported by its chunk, but a grounded claim can still answer a RELATED-BUT-DIFFERENT question than asked. A node runs after `verify` on the grounded path, before `compose` (`verify --grounded--> assess_relevance --> compose | refuse`): `RelevanceAssessment {responsive, reason}` asks whether the verified draft addresses the SPECIFIC question; a non-responsive verdict routes to `refuse`. **Deliberately conservative** — the prompt defaults to responsive; premise-rejections ("there is no such option") and short/partial on-topic answers stay responsive — so it removes ONLY clear question/answer topic mismatches, not legitimate answers. Motivating case slide-decks-30: the CUDA deck's "C++/Python abstractions for tensor cores" grounds a library-usage claim the agent passed off as the answer to "which language writes CUDA *kernels*" (grounded, but a conflation). GPU-validated multi-run (slide-decks-30 refuses reliably; no over-refusal on clear-answer corpora). **Load-bearing lesson:** tuning the `assess_sufficiency` prompt for this was WHACK-A-MOLE — the apparent v1-vs-v2 regressions were **eval non-determinism** (borderline counterfactuals flip run-to-run under the agent's BF16/AWQ greedy decode; a v1-revert showed the SAME flips). `refusal_cf=1.0` is a single-run metric — **measure borderline-gate changes multi-run**. The gate is a SECOND orthogonal filter (lowers the conflation flip rate), NOT a determinism fix; it does NOT catch cross-doc SCOPE conflations (cr350-diag-12 answered "firewall-diagram VLAN range" from semaine-4's VLAN content — responsive but wrong source; that's multi-doc disambiguation, **now fixed deterministically by the artifact→doc re-scope below**). Pinned by `test_answering_with_fakes.py::test_non_responsive_grounded_answer_is_refused`; the 4 graph-exercising test fakes default `RelevanceAssessment`→responsive.
- **`route_after_verify` ships the GROUNDED SUBSET on a partial-grounded draft** (2026-05-26, the compound-question over-refusal fix). Verification grounds CLAIMS individually, so a draft can come back MIXED — some grounded, some not (e.g. a compound question whose groundable half the corpus supports and whose other half it doesn't). The router used to be all-or-nothing: `all_grounded → compose`, else regenerate-then-**refuse** — so a regen that couldn't ground *everything* discarded the whole answer (incl. the groundable half). Now: still regenerate while budget+attempts remain (the answer node gets the ungrounded-claim feedback and tries to ground the rest); but once **exhausted (or over budget)**, if a NON-EMPTY grounded subset survives, route to `compose` (→ via `assess_relevance`) to ship it — `compose` drops the ungrounded claims (its existing defense-in-depth) AND **rebuilds the summary from the surviving claims** (`summary = " ".join(c.claim …)` when any claim was dropped) so no ungrounded assertion leaks into the headline. **Only a ZERO-grounded verdict refuses**, so counterfactuals are unaffected (`refusal_cf` preserved — GPU-validated multi-run on the counterfactual corpora). HARD-gate-safe by construction: ships only verified-grounded claims, vetted by the (already-grounded-subset-judging) relevance gate; worst case is a relevance miss (a grounded-but-off-topic subset), never a hallucination. The answer-node "drop ungroundable claims" prompt feedback is NOT enough alone — the LLM keeps trying to answer an explicitly-asked sub-question (observed live), which is why the fix is deterministic in the router, not the prompt. Helper `_has_grounded_claims` mirrors compose's surviving-claims test (valid index in range). Kill-switch `agents.partial_grounded_answers` (env `MEMEX_AGENTS__PARTIAL_GROUNDED_ANSWERS=false`, read fail-open in `answer_query` → `AnswerState.allow_partial_grounded`; the router stays pure, reading state). Pinned by `tests/unit/test_answer_routing.py` (the routing matrix + `_has_grounded_claims` phantom-index handling) + `test_answering_with_fakes.py` (partial ship drops the ungrounded claim + rebuilds the summary; zero-grounded still refuses; kill-switch reverts to all-or-nothing; `test_verify_missing_index_treated_as_ungrounded` now asserts the omitted claim is *dropped*, not whole-answer-refused).
- **A named artifact deterministically re-scopes retrieval to its document(s)** (#256, 2026-05-26, `agents/artifact_scope.py` + `agents/answering.py::resolve_artifact_scope`, spec `docs/specs/artifact-scope.md`). When a query NAMES a specific artifact ("le diagramme de coupe-feu", "the Gantt chart"), a node between `retrieve` and `expand_graph` resolves it to the doc(s) it lives in and **REPLACES** the candidate pool with `hybrid_search_in_docs(query, scope_docs, k=50)` — the named artifact is an automatic doc-selection. Two PURE stages (`detect_artifact_reference` regex EN+FR → `resolve_scope` per-token BM25), **no LLM** (the determinism mandate — an earlier LLM `assess_relevance` source-scope clause was validated ineffective and reverted, Qwen3-8B gave 0 non-responsive verdicts). For cr350-diag-12 this makes the refusal DETERMINISTIC by construction: the re-scope removes semaine-4's VLAN chunk from the pool before the LLM sees it, so there's no VLAN evidence to (mis)answer from regardless of greedy sampling. **The positional qualifier rule is load-bearing**: FR `diagramme de <tail>` captures the tail AFTER the connector ({coupe,feu}) and the data term precedes the noun (so 'vlan' is excluded for diag-12), while the near-twin "diagramme de configuration VLAN" INCLUDES vlan → scopes to the VLAN deck (answers). **The single-token specificity gate is also load-bearing**: a LONE qualifier token only scopes when distinctive (title hit OR sole-doc), else no-scope — this blocks the slide-decks-04 "TSMC chart" mis-scope (the CUDA deck's in-chart "tsmc" is FTS-stripped, so the bare token dominantly matches the 10-K's prose mentions → would false-refuse an ANS query); multi-token qualifiers (where every #256 fix lives) are exempt. **Conservative + fail-open + HARD-gate-safe by construction**: no artifact / no confident resolution / kill-switch (`MEMEX_AGENTS__ARTIFACT_SCOPE_ENABLED=false`) / any store error all leave candidates untouched (the full-corpus path); the node can only NARROW retrieval, never add a chunk or relax a gate, so the worst case is a conservative false-refuse on a mis-resolved ANS query, never a hallucination or wrongly-answered counterfactual. `expand_graph` short-circuits while a scope is active (else it would re-admit out-of-scope chunks). Pinned by `tests/unit/test_artifact_scope.py` (detection/resolution tables, the diag-12-vs-img-01 discriminator, the single-token gate, N=50 determinism) + `test_answering_with_fakes.py` (re-scope refuses wrong-source / near-twin answers / no-artifact no-op / fail-open / kill-switch / expand_graph-skip). The lazy `FTSStore.open` inside the resolver follows the documented `agents/ → index/` lazy-store edge (same as `expand_graph`/`query_tables`). **The resolved scope is surfaced on `FinalResponse.artifact_scope_doc_ids`** (populated in `compose` + `refuse` from `state.artifact_scope_doc_ids`; `[]` on the full-corpus path) so the re-scope is auditable — on a refusal it explains WHY the pool was narrowed (ADR-0004, observable at every layer). HARD-gate-neutral (a derived observability field, never alters answered/claims/refusal); MCP/CLI auto-serialize it, and the webui answer panel renders a quiet "Scoped to …" note (`.ans-scope`). **The explicit doc-picker (2026-05-27) rides the SAME node:** `answer_query(scope_doc_ids=[...])` (the webui's `<details>` checklist → `/ask` Form list; MCP `ask`'s `scope_doc_ids`; CLI `--doc`) sets `AnswerState.scope_doc_ids`, which `resolve_artifact_scope` honors FIRST — scoping to exactly those docs (dedup + blank-strip) and TAKING PRECEDENCE over inference (no `detect_artifact_reference`, no FTS resolver). It writes the same `artifact_scope_doc_ids` (the *applied* scope), so the surfacing + the `expand_graph` short-circuit are shared; worst case is an empty scoped pool → clean refuse (HARD-gate-safe — only narrows). Pinned by the explicit-scope tests in `test_answering_with_fakes.py` (answers-from-pick / precedence-over-artifact / dedup / empty-scope-full-corpus / scoped-can't-answer-refuses / empty-pool-clean-refuse) + `test_webui.py` (picker renders, scope forwarded, "your selected" label) + `test_mcp_server.py`. Spec `docs/specs/artifact-scope.md`. **Saved scope sets (2026-05-27, `core/scope_sets.py`, spec `docs/specs/scope-sets.md`)** are the PERSISTENCE layer over the picker: a named `doc_ids` collection stored as a single atomically-written JSON at `vault/.memex/scope_sets.json` (mirrors `core/manifest.py`'s `mkstemp`→`fsync`→`os.replace`; **user-authored, so deliberately NOT in the `reindex_vault(force=True)` teardown allow-list** — a full rebuild preserves it). A set is purely a naming layer that resolves to `doc_ids` AT THE SURFACE and feeds the EXISTING `answer_query(scope_doc_ids=...)` path — **the agent never imports `scope_sets`** (no new agent coupling), and the same HARD-gate guarantee holds (a stale set whose docs were removed resolves to an empty pool → clean refuse). Surfaces: CLI `memex scope-set create|list|show|delete` + `memex ask --scope-set NAME`; MCP `ask(scope_set=)` (unknown name → `ConfigurationError`, never a silent full-corpus search) + a new `list_scope_sets` tool; webui `_scope_picker.html` saved-set bar (apply re-ticks the boxes server-side; `/ask` stays `scope_doc_ids`-only). `read_scope_sets` raises `VaultIntegrityError` on a corrupt store (loud at the management surface) while `resolve_scope_set_doc_ids` fails OPEN to `[]` (a corrupt file never breaks `ask`); name lookup is case/whitespace-insensitive (`normalize_set_name`), the set NAME is a JSON value never a path component (no traversal risk). Pinned by `tests/unit/test_scope_sets.py` (CRUD/upsert-preserves-created_at/dedup/validation/corrupt-raises-vs-resolve-fails-open/ordering-determinism) + `test_webui.py` (save→appears, apply→pre-checks, delete→removed) + `test_mcp_server.py` (scope_set unions doc_ids, unknown raises, `list_scope_sets`).
- **The chunker attributes each chunk to its source PDF page (`Chunk.page`)** (2026-05-27, `index/chunker.py::chunk_document(..., page_char_counts=...)` + `page_intervals` + `_page_for_offset`). Each parse path now records per-page markdown length on `PageDecision.char_count` (in `ParseStage.pages`); `index_document` reads them from the manifest and feeds them to the chunker, which cumulates `(char_start, char_end)` per page (delimiter `"\\n\\n"` = 2 chars, consistent across PyMuPDF/Docling/scan) and binary-searches each chunk's `char_start` into the intervals. Drives the webui's click-source→jump-to-PDF-page UX (`_source_view` surfaces `Chunk.page` into `chunk_refs[chunk_id].page`; `_answer.html`/`_summary.html` emit `data-page="N"` + the URL gains `?page=N#section-slug`; the doc-page's inline `<script>` scrolls the preview pane to `#page-N` on landing + on same-doc clicks). **Legacy manifests** written before `PageDecision.char_count` existed carry all-zero counts → `page_intervals` returns `None` (the "no mapping" sentinel) → `Chunk.page` stays `None` → the webui falls back to section-only anchors (no regression, no required re-parse). **Page mapping is navigation-grade, not citation-grade** — post-stitch transforms (`_stitch_chart_extractions` adds chart blocks at placeholder sites; `_finalize_body`'s `linearize_gfm_tables` appends `[table-rows]` after every GFM table) shift offsets downstream, so a chunk near a page boundary can be attributed to the wrong page by ~1; acceptable for click-to-jump. The Docling path re-records `char_count` AFTER the VLM-escalation stitch (so escalated pages report the VLM-transcribed length, not the original Docling output). HARD-gate-neutral (derived metadata; never alters retrieval or grounding). Pinned by `tests/unit/test_chunker.py` (page_intervals cumulative + zero-sentinel + `_page_for_offset` + `chunk_document(page_char_counts=...)` populates `Chunk.page`).

- **A scanned/handwritten PDF (image-only, no text layer) routes to a WHOLE-DOC VLM transcription, NOT Docling-OCR** (2026-05-27, `parse/pipeline.py::_parse_scan_with_vlm` + the pure `_assemble_scan_pages`; spec `docs/specs/scan-vlm-parse.md`). After the PyMuPDF pre-filter punts, `_parse_pdf` dispatches to the scan route ONLY when `is_scan AND not parse.disable_vlm AND suffix == ".pdf"` — purely ADDITIVE: **`disable_vlm=True` (the default) keeps the old Docling-OCR fallthrough** (no regression), and `force_docling=True` skips the pre-filter entirely (the scan route is the AUTO path only — don't force-docling a scan). It transcribes ALL pages 1-based via `convert_pages` under one `pause_vllm_for_gpu()` (nestable → the CLI's outer pause no-ops it), `_assemble_scan_pages` stitches readable pages in reading order (a failed page → `PageDecision(engine="scan", confidence=0.0)` with the error in `rationale`, never a silent drop), then `_finalize_body` + `write_document` + a `ParseStage` with `engine="scan"` pages (`manifest.PageDecision.engine` Literal gained `"scan"`). **No chart-OCR pass** (the VLM transcribes diagrams inline → no `<!-- image -->` placeholders to stitch). All-pages-fail → empty body → 0 chunks → answer/summarize REFUSES (HARD-gate-safe; never fabricates from an unreadable scan). The VLM cache makes a re-parse replay (the determinism guarantee extends to scans). Validated end-to-end on a CC-BY handwritten C++ note (scan route fired → faithful transcription → grounded `ask`). Pinned by `tests/unit/test_scan_route.py` (the pure stitch) + `tests/integration/test_scan_routing.py` (transcribe→write→manifest + the `disable_vlm` gate).

- **Table-RAG Phase 2 — the text-to-SQL tool reuses grounding and holds the HARD gate by construction** (2026-05-24). Four invariants future contributors MUST preserve: **(a)** a SQL answer is injected as a **synthetic `Chunk`** into `state.reranked` (chunk_id `<doc_id>#sql0001`) by the `query_tables` node (between `rerank` and `assess`) — the existing assess/answer/verify/compose machinery then cites it like any other chunk. Do NOT invent a new grounding path or a LangGraph `ToolNode`; the synthetic-chunk seam is the whole point. **(b)** The **row-vs-aggregate fabrication boundary** is load-bearing: a hallucination is a value the doc doesn't contain. Row-returning SQL ships **verbatim document cells** (safe to inject). Aggregate SQL ships a **new number**, so it's injected ONLY when `agents/table_sql.py::_recompute_aggregate` (an independent Python recompute over the original cell text) agrees — otherwise the node is a no-op and the agent refuses. Never inject an unverified aggregate; that breaks the `refusal_cf=1.0` / zero-hallucination HARD gate. **(c)** `_compute_schemas` is the **single source of truth** for sanitized SQL identifiers — the `generate_table_sql` prompt AND `_load_tables` must consume the *same* schema, and the prompt must NEVER show unsanitized column/table names (a name mismatch makes the model emit SQL that can't execute). **(d)** `tables.sqlite` (`~/.memex/vault/.memex/tables.sqlite`) is **regenerable derived state** (ADR-0003) built in `index_document` via `index/table_store.py::TableStore.extract_tables` (reuses the Phase-1 GFM parser + header-sanity gate — well-formed tables only); it's in the `reindex --force` teardown. `query_tables` opening `TableStore` lazily inside the node follows the already-documented `agents/ → index/` lazy-store-open edge (same as `expand_graph`/`GraphStore`).

## Errors

- Every raise uses a `MemexError` subclass from `core/errors.py`. Subclasses today: `InsufficientVRAMError`, `ParseConfidenceTooLow`, `RetrievalEmpty`, `VaultIntegrityError`, `IndexOutOfSync`, `ConfigurationError`, `StaleDocumentError`, `AnswerStateInvariantError`, `ModelCallError`, `ScopeSetError`. Module-local subclasses are fine as long as they inherit from `MemexError` — current ones: `CircuitBreakerOpen` (core/breakers.py); `ModelNotConfigured` (models/registry.py); `VLMUnavailable`, `PDFRenderError` (parse/vlm_backend.py); `ChartOCRUnavailable`, `PDFFigureRenderError` (parse/chart_ocr_backend.py); `DoclingUnavailable`, `DoclingTimeout`, `DoclingCrashed`, `SandboxLoadFailed` (parse/docling_backend.py); `PyMuPDFUnavailable`, `PyMuPDFTimeout`, `PyMuPDFCrashed` (parse/pymupdf_backend.py); `DaemonAlreadyRunning`, `DaemonStartTimeout` (daemon/supervisor.py).
- Every raise carries a `context: dict` with the values a user needs to act on the error.
- Recoverable errors set `recoverable=True` so the pipeline knows to resume on retry.
- **Narrow `except` clauses.** Never `except BaseException` (would swallow `CancelledError`, `KeyboardInterrupt`, `SystemExit`); never `except Exception` unless you re-raise the cancellation cases above explicitly. When wrapping a third-party SDK exception, check the module via `type(e).__module__.startswith(...)` rather than catching the broad base class.

## Async / sync

- **Async**: filesystem I/O, model calls, database operations, HTTP, MCP transport.
- **Sync**: token parsing, formatting, chunker, pure transformations.
- CPU-heavy sync work called from async code goes through `asyncio.to_thread` (`models/registry.py` does this for sentence-transformers `encode`; `index/fts_store.py` for sync SQLite).
- **Per-resource locking** is `asyncio.Lock` for stores serving async callers (`index/fts_store.py::FTSStore._lock` gates multi-statement writes; `vault/store.py::_DOC_LOCKS` gates per-doc write paths) and `threading.Lock` for state that crosses both sync and async callers (`agents/answering.py::_COMPILED_GRAPH_LOCK` gates the lazy graph compile). Don't mix the two — pick by who the callers are. The `models/registry.py::_locks` per-model dict + the breaker's lock are the canonical patterns to copy.

## Logging

structlog. Bind once per run scope at the entry point (`bind_run_context(correlation_id, ...)`), bind node/function scope locally (`log = logger.bind(node="rerank")`), emit `log.info("event", k=v)`. **Never** `extra={...}` (lost), **never** f-strings in event names (kills aggregation in Langfuse).

## CUDA

ADR-0006 settles it. The summary:

- **bf16** is the dtype across the stack on Ada. Embedder, reranker, VLM, and chart-OCR all use explicit `torch_dtype=torch.bfloat16`. (FP16 is forbidden for EmbeddingGemma — its activations don't support it.)
- **FA2** for the VLM (`attn_implementation="flash_attention_2"`). FA3 is unavailable on sm_89.
- **`device_map={"": "cuda:0"}`** — deterministic single-GPU placement, not `"auto"`.
- **Retrieval device override (2026-05-27):** `ModelSettings.{embedder,reranker}_device` (`"cuda"` default, or `"cpu"`) places the embedder/reranker on CPU (fp32 via `registry._retrieval_dtype`) to free GPU VRAM for a full-util orchestrator KV cache on a single 12 GB card. `_do_load` passes the device to `_load_embedder`/`_load_reranker`/`_load_reranker_qwen3`; the retrieval path already follows each model's own device (`rerank.py` reads `next(model.parameters()).device`), so no other change. `bootstrap._estimated_vram_gb` (the now-pure, testable VRAM estimate) excludes a CPU-placed model. Trade-off = ~20 s CPU rerank latency vs a squeezed KV at lower util (ADR-0006 §2 amendment). Pinned by `tests/unit/test_retrieval_device.py`.
- **Co-residence MODES are a policy layer over those device knobs (2026-05-27, ADR-0007, `core/resources.py`).** `ModelSettings.co_residence_mode` (`fast`/`full`/`gpu_only`/`manual`, default `manual`) resolves via the PURE `resolve_profile(mode, *, total_vram_gb, embedder_device, reranker_device) -> ResourceProfile` — the SINGLE place the VRAM tradeoff is encoded, and the seam a future dynamic VRAM manager replaces (compute the profile from live free-VRAM) without touching callers. Consumers: `registry._do_load` calls `effective_devices(...)` (a curated mode OVERRIDES the explicit device knobs; `manual` honors them); `bootstrap._estimated_vram_gb` uses the effective devices; the daemon (`daemon.supervisor.restart(gpu_fraction=, max_model_len=)`) launches vLLM with the profile's `orchestrator_gpu_fraction`/`orchestrator_max_model_len` (via the `MEMEX_VLLM_*` env the serve script reads); the CLI (`memex mode show|set`, `memex daemon restart`); the webui (`/resources` page + the header `active_mode_label` jinja global). `manual` is the default → fully backward-compatible. `core/resources.py` is PURE (no `config` import → no cycle; `config` imports IT for the `CoResidenceMode` Literal). `core/config.py::config_toml_path()` is exposed for `memex mode set`'s persist instruction. Pinned by `tests/unit/test_resources.py` + the registry-mode + webui `/resources` + daemon-restart tests. **`full` mode raises `max_model_len` (~24,576)** — originally for the free-form `agents/synthesize.py` baseline; the production summarizer below no longer NEEDS it (it's mode-independent by construction), but `full` still allows the eventual short-route single-shot on a bigger small-doc. **The supervisor's PID-identity guard recognizes the `exec`'d daemon (2026-05-27 fix):** `serve-vllm.sh` ends in `exec uv run … vllm serve …`, which REPLACES the script's process image, so the tracked PID's `/proc/<pid>/cmdline` shows the `vllm serve` invocation and NOT the script path — `daemon.supervisor._argv_matches_daemon` therefore accepts EITHER the script name OR the durable `vllm serve` + `--port <PORT>` signature (port pins identity against PID reuse). Before this, `_pid_owns_script` matched only the script name → it returned False for EVERY properly-started daemon → `stop()`/`restart()`/`mode set`/`daemon restart` silently logged `pid_reused_clearing_file` and refused to kill the daemon (a real, validated-live bug). Pinned by `tests/unit/test_supervisor_pid_alive.py`.
- **The document summarizer is doc-type-aware, structured, and GROUNDED — quality is mode-independent BY CONSTRUCTION (2026-05-27, ADR-0008, `agents/document_summarizer.py`, spec `docs/specs/document-summarization.md`).** `summarize_document(doc_id, *, instruction, detail, max_output_tokens, token_budget) -> FinalResponse` is a standalone async MAP→GROUND→REDUCE (NOT a LangGraph): load the doc's stored chunks via `FTSStore.chunks_for_document` (the boundary-correct primitive — `agents/ → index/`, never `vault/`), group by heading-section, route (`short`/`long`; **`tabular` shipped** — see below; `deck`/`scan` deferred → `long`), MAP each section to a `SectionSummary`, **GROUND its key-points by reusing `verify_grounding/v2` verbatim** (wrap the `CitedClaim` key-points in a `DraftAnswer`, keep only confirmed-grounded indices), REDUCE the grounded digests to a `DocAbstract`. Four load-bearing contracts: **(a)** output is `maxItems`-bounded lists of SHORT bounded strings (`SectionSummary.key_points` ≤8, `digest`≤600; **`DocAbstract` is itself a ≤8-item list of ≤300-char `sentences` joined by an `abstract` property, ADR-0009** — NOT a single capped string) — the reliable shape because each short item ends at a NATURAL boundary and `maxItems` bounds the COUNT, vs a single free-form string that force-closes MID-WORD at its cap (the "policyEn" cut) and invites whole-doc regurgitation. **(Correction 2026-05-28: the pinned stack DOES enforce string `max_length` — probe-verified, consistent with the schema-bound rule above; the earlier "enforces `maxItems` but NOT `maxLength`" framing was STALE. The list win is natural-boundaries + count-bound + grounding, not a `maxLength` gap. See ADR-0009.)** **(b)** Zero grounded points → `answered=False` REFUSAL — the HARD gate (refusal_cf=1.0, 0 hallucinations) extended to summaries; the summarizer can only narrow what it emits, never assert ungrounded. **(c)** Quality is INDEPENDENT of `co_residence_mode` BY CONSTRUCTION: `summarize_document` never reads the mode, and every LLM call is bounded to fit the SMALLEST (`fast`/6144) window — `_bound_section_chunks` caps the per-section input to `_MAX_SECTION_INPUT_CHARS` (**10k RENDERED chars** via `_chunk_budget_chars`, which counts each chunk's prompt WRAPPER — the ~65-char content-addressed chunk_id + repeated doc title + formatting — not just text; the old 12k TEXT-only budget under-counted a packed deck's 20-59 tiny slide-chunk wrappers by thousands of chars → a "9.5k-text" group rendered to ~18k chars/6.6k tokens → MAP 400'd → section silently DROPPED; fixed 2026-05-28) and feeds the SAME set to MAP and GROUND, GROUND/REDUCE cap output (`_VERIFY_MAX_TOKENS`/`_REDUCE_MAX_TOKENS`) + REDUCE caps digests to `_REDUCE_MAX_SECTIONS`, so the input is identical in `fast` and `full` (validated live: same 9 sections / 12 grounded claims / faithful abstract in both modes, no window-overflow). A section bigger than the budget is **sub-split** across window-sized batches (`_split_section_into_batches`, the per-group loop; each batch → its own `(part k)` SectionSummary, every chunk in exactly one batch → no content dropped; the abstract REDUCEs whenever >1 summary). **(d)** `detail` (`brief`/`standard`/`detailed`/`report`) threads length guidance into the prompts (`_DETAIL_GUIDANCE`) — the requested verbosity within the hard schema bounds. **`report` (ADR-0010) switches REDUCE to the HIERARCHICAL `_reduce_report`:** the grounded section digests are batched `_REPORT_SECTIONS_PER_BATCH` (4) at a time, each batch → one bounded `DocAbstract` paragraph (reusing `_reduce`, hence the same validated primitive + a `scope_note` so a batch doesn't claim whole-doc scope), then stitched DETERMINISTICALLY with blank lines — NO final whole-output pass (that would reintroduce ADR-0009's free-form trap). Every section reaches the output (no `_REDUCE_MAX_SECTIONS` truncation; the safe inverse of free-form synthesis); the webui splits the `\n\n` body into one `<p>` per paragraph in one `.ans-answer`. **Coherence refinements (ADR-0010 §Refinements):** (i) ROLLING context — `_reduce` takes a `preceding` param (the prior paragraph) so each one transitions + adds only new material (not disjoint "The document focuses on…" blocks); (ii) an OPEN/middle/CLOSE arc via position-aware `scope_note`; (iii) ADAPTIVE structure — `_plan_report_structure` lets the model pick paragraph breaks by **boundary-selection** (`ReportStructure.paragraph_starts` — can't drop/dup a section), size-capped + **fallback to mechanical batching** on a trivial/failed plan, all logged (`report.plan*`); (iv) inform-only **faithfulness confidence** — `_score_report_confidence` → `ReportConfidence` on `FinalResponse.report_confidence` (hybrid lexical-overlap + best-effort embedder cosine of each paragraph vs its source digests; surfaced + logged `report.confidence`, NEVER a gate); (v) a DETERMINISTIC cross-paragraph **dedup gate** (`_dedup_sentences`, `_REPORT_DEDUP_THRESHOLD`=0.7 overlap-precision, 2026-05-28) drops a sentence whose content tokens are already >70% covered by a SINGLE earlier kept sentence — the 8B re-covers a TOPIC when its sections overlap a prior paragraph's DESPITE the branched prompt + full rolling context (topic-aware planning can't fix it on decks' coarse/noisy recovered headings); LEXICAL → always-on + reproducible (the confidence embedder degrades under VRAM pressure, can't be the dedup signal), HARD-gate-safe (only removes already-grounded prose → can't add an ungrounded assertion), logged `report.dedup`; `_reduce` now returns the `DocAbstract` so dedup runs at sentence granularity. All five keep the bounded/grounded invariant + are HARD-gate-neutral (grouping/scoring/removal only). **The granularity is TUNED (2026-05-28):** `report_pack_chars` (default 4000) + `report_coalesce_target` (default 2) on `AgentsSettings` (env-overridable, report-mode only) are the swept winner from the report-STRUCTURE validator (`scripts/report_structure_audit.py` + `tests/eval-data/report-structure/`); a narrower pack → tighter per-paragraph grounding → the granularity↔repetition tension didn't exist (more paragraphs AND higher confidence AND higher distinctness, 0 leaks). - **Fakes accept forward-compatible kwargs.** When you write a stand-in for `complete_structured` (or any other function with optional kwargs), terminate the signature with `**_kw: object` so adding a new kwarg upstream doesn't silently break the test. - **Patch via `monkeypatch.setattr`**, never direct module-attribute mutation. The latter leaks into subsequent tests in the same session.

## When adding a new module

1. Check the architectural blueprint — module signatures are already designed in `docs/IMPLEMENTATION-PLAN.md` §1.
2. Update `src/memex/<module>/__init__.py` to re-export the public surface.
3. Add an integration test under `tests/integration/`. Fake every external (`monkeypatch.setattr`).
4. Wire to the CLI under `cli/commands.py` if user-facing.
5. Update `docs/ROADMAP.md` if the module ships a phase deliverable.
