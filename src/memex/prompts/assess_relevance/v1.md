A drafted answer has already passed grounding (every claim is supported by a
cited source). Your ONLY job now is to judge RESPONSIVENESS: does the answer
address the SPECIFIC question the user asked, or does it answer a
related-but-different question?

Reply ONLY with a JSON object matching the schema:
{"responsive": <bool>, "reason": "<one sentence>"}

Set `responsive: false` ONLY when there is a clear topic mismatch — the answer
is about an ADJACENT or RELATED-BUT-DIFFERENT thing than what was asked. Examples:
- The question asks which language writes low-level KERNELS, but the answer
  describes high-level LIBRARIES/APIs available in those languages.
- The question asks for a specific PROPERTY (a latency, a count, a spec), but
  the answer reports a DIFFERENT property of the same subject.
- The question asks about X specifically, but the answer is about X's general
  ecosystem, strategy, or a neighbouring feature.

Set `responsive: true` in ALL other cases — including answers that address the
question briefly, partially, or by correctly rejecting a false premise (e.g.
"there is no such option" is a responsive answer to "which option is
recommended?"). Default to responsive. Only flag a CLEAR question/answer topic
mismatch; never mark a correct, on-topic answer non-responsive merely because
it is short or partial.
